# 手アニメーションのモバイル性能改善 設計

## 1. 目的

スマートフォン相当の画面で石を置く手アニメーションがかくつく問題を、モバイル限定の演出削減ではなく、通常経路に残っている不要な画像切替・DOM更新・レイアウト計測を減らして改善する。

対象は配置手アニメーションと、それに伴うカードUI再同期である。石の確定、スポーン、反転、手の退避、入力再開の順序と所要時間は変更しない。

## 2. 根拠

調査時の計測では、待機中5秒の `TaskDuration` は約1.4ms、DOM mutationは0であり、常時走るバックグラウンド処理は主因ではなかった。

一方、配置手アニメーション1回につきカードUI側で53件のDOM mutationが発生した。黒の操作と白CPU応答を1往復させると、手表示ありは手表示なしより正確に106件多く、2回分の53件と一致した。無効状態で手表示後の再同期だけを100回実行したCPU 4倍スロットル計測では、1回あたり約12.1msの `TaskDuration`、約1.67msのLayout、約1.68msのRecalcStyle、およそ10個のdetached nodeが発生した。

また、単一の `#handImage` をプレイヤー用とCPU用で共有していたため、CPU手表示時と終了時に `src` を往復させていた。ローカルのno-store配信では1回の手表示で2回の画像応答が発生し、公開配信でも初回は再検証が入った。これは常時のフレーム落ちだけを説明するものではないが、コールド時の画像取得・デコードをアニメーション開始経路に持ち込む設計上の負荷である。

CSSのfilter・shadow・backdrop-filterの除去、DPR変更、CPUスロットルだけでは、安定状態のrAF最大値は有意に変化しなかった。そのため、モバイルでCSS効果だけを無効化する対処は採用しない。

## 3. 設計

### 3.1 手画像を役割別に保持する

- `#handImage` は画面側で同期済みの基準手スキンを保持し、演出中に書き換えない。
- CPU・相手・再生イベントなど、アニメーション主体が別スキンを要求する場合は、手アニメーション層が管理するactor画像を別要素として生成・再利用する。
- actor画像は解決済み画像パス単位で保持し、同じ画像を使う次のアニメーションでは要素とデコード済み資源を再利用する。
- アニメーション中だけ表示対象を切り替え、終了時はvisibilityを戻す。`#handImage.src` をCPU画像へ変更してから元へ戻す処理は行わない。
- 画像パスの決定は既存のhand-skin runtimeを唯一の正本とし、CPUレベル解決ロジックをアニメーション側へ複製しない。

### 3.2 カードUI再同期を差分適用にする

配置手アニメーションの終了時には、busy/animation状態の解除後にカード操作可否を再評価する必要がある。この安全弁自体は残す。

そのうえで、全カードUI再同期が呼ばれても、値が変わっていない `textContent`、dataset、style、属性を再代入しない。カード詳細の本文・タグも表示モデルの署名が同じなら再構築しない。

手札グロー層は、カード状態の署名とdirty状態が変わっていない場合、レイアウト環境キーを作る前に終了する。ResizeObserverと明示的なdirty化があるため、状態不変時に `clientWidth`、`clientHeight`、scroll値を読む必要はない。

これにより、配置演出後の正当な操作状態更新は保ちながら、変更のないカード・山札・捨て札・詳細欄を作り直す処理を除去する。

### 3.3 表示順序と責務を維持する

- `01-rulebook.md` に定める約0.44秒の配置手アニメーションと、接触時に石のスポーン・反転へ進む順序は変更しない。
- canonical game state、`events[]`、Pixi board writerには触れない。
- 手/HUDから盤面への軌道は既存どおりDOM presentation層に置き、盤面ピクセルのwriterは増やさない。
- 処理中フラグやカードアニメーションフラグを早く解除して見かけ上軽くすることはしない。

## 4. 採用しない案

- スマートフォンだけ手アニメーションを無効化する: 症状を隠すだけで、不要な全UI再同期と画像差し替え設計が残る。
- 終了時のカードUI再同期を単純に削除する: 演出中に描画されたdisabled状態が残り、入力再開後も操作不能になる危険がある。
- CSS効果だけを削除する: 計測で主要因と確認できず、視覚品質だけを落とす。
- 手の退避完了まで石の確定を遅らせる: プレイヤー向けの時間仕様とテンポを変更する。

## 5. 完了条件

1. 黒・白CPUの配置手アニメーション中も、基準表示用 `#handImage.src` が変化しない。
2. 同一actor画像を使う2回目以降の配置手アニメーションでactor要素が再利用される。
3. actor要素生成後の配置手アニメーション単体のDOM mutationが、調査時の53件から15件以下へ減る。
4. 黒操作＋白CPU応答の1往復で、手表示あり/なしのDOM mutation差が106件から30件以下へ減る。
5. 手アニメーションの接触、スポーン、反転、退避、busy解除、入力再開の既存順序とタイミングテストが通る。
6. アニメーション後にカード操作がdisabledのまま残らない。
7. ハードウェアアクセラレーション有効のモバイルviewport検証でLongTaskが0、手アニメーション中のrAF最大間隔が20ms以下である。
8. ブラウザ実画面のスクリーンショットで、手・石・カードUIに新しい重なり、ちらつき、欠落がない。

## 6. 自己レビュー

- 仕様変更ではなく内部の表示資源管理と差分描画なので、`01-rulebook.md` と `正本/` の更新は不要。
- actor画像の新設は盤面writerを追加せず、DOM-ownedの手演出内に閉じる。
- UI再同期を残すため、busy解除後の操作復帰という安全性を維持できる。
- actor要素の無制限増加を避けるため、解決済み画像パスごとのキャッシュとし、想定される手スキン集合に限定する。
- 計測目標を満たさない場合は、UI再同期削除で帳尻を合わせず、mutationの残存箇所を再計測して設計を改訂する。

## 7. 実装後の検証結果

- 配置手アニメーション単体: 初回はactor要素生成を含め28 mutation、同じactorを再利用する2回目は15 mutation。調査時の継続値53から38件減少した。
- 単体演出のrAF最大間隔: 初回8.3ms、2回目4.3ms。LongTaskはいずれも0。
- 黒操作＋白CPU応答の実対局1往復: 配置演出ONは519 mutation、配置演出OFFは503 mutationで差は16。調査時の差106から90件減少した。
- 実対局の配置手アニメーション: rAF最大8.4ms、20ms超0回、LongTask 0。
- `#handImage.src`: 実対局と単体演出の開始前後で `assets/images/hand-skin/lv1-2.png` のまま不変。別主体は再利用actor要素で表示された。
- キャッシュ済み実対局では手スキンの追加resource requestは0。終了時はactor active数0、actor総数1、ローカル手札のclickableカード2枚、Pixi canvas 1枚だった。
- 844×390のモバイル横画面で、配置中とCPU応答後をスクリーンショット確認し、手・石・カードUIの欠落、二重表示、残留overlayは見られなかった。
