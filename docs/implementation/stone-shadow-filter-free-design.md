# 石影の実行時ブラー撤去 設計書

## 文書の役割

- 役割: 石影のプレイヤー向け挙動を維持したまま、通常描画とアニメーション時の CSS フィルター負荷を減らす実装設計
- プレイヤー向け仕様の正本: `01-rulebook.md`
- 内部契約の正本: `docs/architecture-contracts.md`
- 非目標: 影のレイヤー数、所有者、位置、変形、表示タイミング、不透明度、石画像、ゲームロジックの変更

## 問題と期待結果

現在の石影は、`.cell.has-disc::before` が盤面に残る投影影、`.disc::before` が石と一緒に反転・移動・消滅する補助影を担当する。両者はそれぞれ `radial-gradient` に `filter: blur()` を適用しているため、終盤盤面では最大 128 個のぼかし付き疑似要素が描画対象になり、多数同時反転では石側の影が親の `transform + filter` アニメーションにも含まれる。

期待結果は、2つの影の所有関係とアニメーション挙動を変えず、実行時の `filter: blur()` を使わない共通の多段減衰グラデーションへ置き換えること。新しい画像アセット、ネットワーク、ゲーム状態、JavaScript の影制御は追加しない。

## リポジトリ上の根拠

- `styles-board.css`: `.cell.has-disc::before` と `.disc::before` が影の形状・位置・変形を定義する。
- `styles-stone-shadows.css`: `stone-shadow-enabled` 時の2層の不透明度を定義する。
- `styles-animations.css`: `.disc.flip`、`.disc.destroy-fade`、移動ゴーストが石側の疑似要素を石と一緒に変形させる。
- `ui/animation-move-events.ts`: 移動ゴーストは `.disc` を複製するため、石側の疑似要素を維持すれば現在の追従動作が残る。
- `docs/archive/stone-rim-shadow-render-refactor-plan-2026-03-20.md`: セル側を projected shadow の正本、石側を補助レイヤーとして扱う既存方針が記録されている。

## 設計

### 選択肢

1. 片方の影レイヤーを削除する
   - 描画数は減るが、盤面に残る影または石へ追従する影のどちらかを失い、ユーザー要件に反する。
2. 事前ぼかし済み PNG を使用する
   - 実行時ブラーを撤去できるが、固定解像度のぼかしがレスポンシブな石サイズに応じて拡縮され、現在の固定 px ブラーと見え方がずれやすい。アセットと manifest 管理も増える。
3. 多段減衰グラデーションでブラーを近似する
   - 影のDOM所有者、座標系、変形、表示タイミングを維持し、CSSだけで `filter` を撤去できる。画像ロードや新しいランタイム経路を増やさない。

### 採用案

選択肢3を採用する。セル影と石影へ共通の多段減衰プロファイルを適用し、各レイヤーは既存の色変数と楕円中心だけを個別指定する。

維持する値:

- セル影の `left`、`right`、`bottom`、`height`、`transform`、`z-index`
- 石影の `inset`、`transform`、`transform-origin`、`z-index`
- `styles-stone-shadows.css` の不透明度 `0.48` / `0.53`
- `stone-shadow-enabled` の有効化経路
- 反転、移動ゴースト、消滅時の既存クラスとアニメーション

変更する値:

- 2つの個別 radial-gradient を、実アセット上で視認できる最小中心強度60%から `52 / 38 / 23 / 10 / 4 / 0%` へ落とす共通の7段階透明度減衰へ統合する。
- `filter: blur(var(...))` を両方から削除する。
- 使用されなくなる2つの blur 用 CSS 変数を削除する。

## 性能方針

- `filter: blur()` による疑似要素ごとのオフスクリーンぼかし面を作らない。
- DOM要素、疑似要素、常設 `will-change`、JavaScript のクラス切り替えを増やさない。
- 影のグラデーションは1つのCSS宣言を両レイヤーで共有し、各石で同じスタイル経路を再利用する。

## テストと検証

- `test/ui.disc-shadow.test.ts` を現在の不透明度と filter-free 契約へ更新する。
- focused Jest で、2層だけが有効であること、両影に `filter: blur()` がないこと、所有者・位置・変形が維持されることを確認する。
- 変更前後の盤面スクリーンショットを同一条件で取得し、実際の通常石画像と盤面テクスチャ上で、石影の存在、方向、重なり、黒石・白石の視認性を確認する。fallback色だけの簡易石は最終視覚判定に使わない。
- `npm run build:browser` と `npm run worker:prepare` を実行し、root と Worker mirror を同期する。
- `git diff --check` と task-owned diff を確認する。

## リスクと緩和

- ガウシアンブラーと多段グラデーションはピクセル単位では完全同一にならない。影の所有者・アニメーション・範囲を固定し、スクリーンショット比較で減衰だけを調整する。
- 暗い盤面テクスチャと通常石画像の組み合わせでは、簡易fallback盤面より影が埋もれやすい。実アセット表示で影が見える最小濃度を選び、過剰な楕円の塊へ戻さない。
- `styles-board.css` と `worker-public/styles-board.css` には別作業の未コミット差分が存在する。正本の対象ハンクだけを編集し、mirror は生成後に対象ハンクだけをコミットする。
- focused test には既に現在の実装と不一致の期待値がある。意図した現行契約へ更新し、テストを弱めずに filter-free 条件を追加する。

## 完了条件

- セル側と石側の2層が維持される。
- 両影から `filter: blur()` がなくなる。
- 影の位置、変形、重なり、不透明度、有効化条件、JS/アニメーション経路が変わらない。
- 同一条件の画面確認で影が欠落せず、方向と立体感が維持される。
- focused Jest、browser build、Worker mirror生成、diff checkが成功する。
- task-owned変更だけをコミットする。

## Self-review

- 初期候補の事前ぼかしPNGは、レスポンシブ拡縮でぼかし幅が変わることとアセット管理増加を理由に採用しなかった。
- 「一層化」ではなく、ユーザーが優先した挙動維持に合わせて2つの座標系を残し、負荷源である実行時ブラーだけを撤去する設計へ限定した。
- 初回のfallback色だけの比較では実ゲーム上の影の視認性を過大評価した。ユーザー提供の実画面で影が見えないことを確認したため、最終QAを実際の通常石画像と盤面テクスチャ必須へ改訂した。
- プレイヤー向けの仕様・タイミング変更ではないため、`01-rulebook.md` と `正本/` は変更しない。
