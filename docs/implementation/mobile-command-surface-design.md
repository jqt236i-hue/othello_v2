# スマホ縦画面コマンドサーフェス移植設計

Role: 現行カードリバーシへ移植したスマホ縦画面用の操作UIと、その保守可能な内部構造を定義する実装設計。
Target: `layout-profile-phone-portrait` のブラウザUI。
Source of truth: プレイヤー向け表示仕様は `01-rulebook.md`、UI/盤面所有境界は `docs/architecture-contracts.md`。
Non-goals: ゲームルール、カード効果、盤面描画、ネットワーク権威、PC/iPad横画面の再設計。

## 問題と目的

現行のスマホ縦画面では、PC用の `#leftActionButtons` と `#quick-controls-bar` を横スクロールトレイとして表示している。機能数が多く、入口が見切れ、盤面下部の表示領域も消費する。

`C:\Users\quarr\Downloads\local-dummy\local-dummy` には、知人が旧版を基に作成した次の有用なUI要素がある。

- 左上の `メニュー` ボタンと全高ドロワー
- 右下の `操作` ボタンとボトムシート
- 設定、見た目、ヘルプ、対戦、コレクション系パネルの全画面縦スクロール表示
- safe area、44pxタップ領域、背景スクロールロック、フォーカス復帰、Escape/ブラウザ戻る操作

目的は、これらを現行ソースへ移植し、古いゲーム実装や補正コードを取り込まずにスマホの入口と操作性を改善することである。

初回移植後の `ui/mobile-command-surface.ts` は、表示生成、設定、代理操作、フォーカス、履歴、既存パネル監視、DOM装飾、破棄を単一関数内で扱う927行の実装になった。挙動は成立しているが、次の保守上・ライフサイクル上の問題が残る。

- `destroy()` が注入要素を属性検索で一括削除する一方、ヘルプの絞り込みボタンを所有要素として記録しておらず、再初期化後にイベントを失ったボタンが残る
- 既存パネルへ追加したclass、`role`、`aria-modal`、折りたたみclassを画面プロファイル離脱時または破棄時に元へ戻さない
- `activeLayer`、`activePanel`、`pendingPanel` が別々の可変値であり、履歴、タイマー、フォーカス起点との有効な組み合わせが型で表現されない
- メニュー項目とパネル設定にトリガーID、表示名、パネルIDが重複する
- DOM生成と代理コントロール同期がコントローラー本体へ埋め込まれ、対象要素ごとに個別 `MutationObserver` を生成する
- `styles-mobile-command-surface.css` が `styles-responsive.css` と同じ盤面・石情報・カード詳細selectorを後勝ちで再定義する

追加の目的は、プレイヤー向け挙動を変えずにこれらの根本原因を解消し、破棄・再初期化、画面回転、戻る操作、将来のパネル追加を局所的に検証できる構造へ改めることである。

初回移植とリファクタリング後の実機確認では、旧スマホ版にあった次のプレイヤー向け要素が移植対象から漏れていることが判明した。

- 右上の `戦況` ボタンと、そこから確認できる「最後に使ったカード／顕現効果」「盤上の石」
- 相手手札の右端に表示する、現在のCPUまたはネット対戦相手のコンパクトなキャラクターアイコン

追加の目的は、現行の戦況・石情報DOMと敵キャラクター状態を表示源としてこの二点を補完し、ゲーム状態や戦況内容の複製を作らないことである。

## スコープ

### 対象

- `layout-profile-phone-portrait` のときだけ表示するスマホ操作レイヤー
- ゲーム、コレクション、情報、設定に分類したメニュードロワー
- リセット、BGM、AUTO、ミュート、BGM選択、全体音量をまとめたボトムシート
- 右上の戦況ボタンと、既存の最後使用カード／顕現効果・盤上の石を表示する戦況ポップアップ
- 相手手札の右端へ置く、現在の敵キャラクターと同期したコンパクトアイコン
- 既存機能パネルのスマホ全画面化
- フォーカストラップ、フォーカス復帰、背景スクロールロック、外側タップ、Escape、ブラウザ戻る操作
- `prefers-reduced-motion`、safe area、44px以上のタップ領域、横方向のページ溢れ防止
- PC/iPad表示の非回帰

### 対象外

- `local-dummy` の `styles-mobile-phase2.css` / `styles-mobile-recovery.css` に含まれる旧盤面座標補正
- `mobile-surface.js` の盤面・手札・CPU選択や戦況内容を複製する独立UI
- 旧版の広域アセットURL書き換え、独自レイアウトプロファイル計算、広域 `MutationObserver`
- Pixi描画、盤面入力、ゲーム状態、ネットワーク状態の変更
- スワイプジェスチャー

## 現行アーキテクチャと根拠

- `ui/layout-stage.ts` が `layout-profile-phone-portrait` と `430x932` 基準のStage変数を所有する。スマホ操作レイヤーはプロファイルを計算し直さない。
- `ui/bootstrap/init-events.ts` が既存ボタンのイベント登録を完了する。スマホ操作レイヤーはその後に初期化し、既存ボタンをクリックまたは入力イベントで代理操作する。
- `#leftActionButtons` と `#quick-controls-bar` が機能・状態の既存DOM正本である。スマホレイヤーはゲーム処理を再実装しない。
- `#manifest-effect-panel` と `#stone-info-panel` が最後使用カード／顕現効果と盤上の石の表示正本である。スマホ戦況は内容をコピーせず、この二つの既存nodeを表示中だけポップアップへ一時配置する。
- `#cpu-character-img` と `#cpu-level-label` が敵表示とCPU設定入口の正本である。スマホ敵アイコンは表示だけを同期し、クリック時は利用可能な既存入口へ委譲する。
- `ui/board-visual/controller.ts` がSingle Visual Writerを所有する。新レイヤーは盤面DOM、canvas、BoardVisualBackendへ書き込まない。
- 各機能パネルは既存コントローラーが `.is-open` / `aria-hidden` を所有する。スマホレイヤーは開閉用の既存トリガーを呼び、スマホ向けの外観・補助ヘッダーだけを付与する。

## 検討案

### A. `local-dummy` を丸ごと上書きする

旧ゲーム実装、旧アセット、独自盤面補正、生成済みJavaScriptまで混ざり、現行のPixi・ネットワーク・レイアウト契約を破るため不採用。

### B. CSSだけで既存トレイをドロワー化する

グルーピング、代理操作、フォーカス管理、戻る操作、BGM選択同期を安全に実現できないため不採用。

### C. 現行ボタンを状態源にした専用プレゼンテーションコントローラー

既存処理を再利用しながら、スマホ固有の表示とアクセシビリティだけを局所化できる。旧版の価値を保ち、現行アーキテクチャへの影響が最小なので採用する。

## 選択設計

### 所有境界

公開facade `ui/mobile-command-surface.ts` とその配下の `ui/mobile-command-surface/*` は次だけを所有する。

- スマホ用ルート、メニュードロワー、ボトムシート、入口ボタンの生成
- 開いているスマホ補助レイヤーのプレゼンテーション状態
- 既存ボタン・select・rangeへの代理入力
- 補助レイヤー内のフォーカスとブラウザ履歴エントリ
- 既存パネルへのスマホ外観クラスと現在位置表示

ゲーム、音声、モード、パネル内容の状態は所有しない。

### 内部モジュール境界

- `config.ts`: メニューと既存パネルの単一コマンドレジストリ、および代理コントロール定義を所有する。メニュー表示とパネル解決は同じ定義から導出する
- `state.ts`: `idle` / `layer` / `panel-pending` / `panel-open` の排他的な表示状態と遷移を純粋関数として所有する
- `history.ts`: 所有トークン付きの単一履歴エントリだけを扱う。表示状態やDOMは所有しない
- `dom-mutations.ts`: 既存DOMに対するclass・属性変更、注入DOM、注入DOMのlistenerをスコープ単位で記録し、元の状態へ復元する
- `view.ts`: スマホ用ルート、ドロワー、操作シートのDOM生成だけを所有する
- `control-proxies.ts`: 既存button/select/rangeへの代理入力と同期を所有し、監視には対象を限定した単一 `MutationObserver` を使う
- `status-bridge.ts`: 戦況ポップアップへの既存nodeの一時配置・復元と、敵キャラクターアイコンの表示／既存入口同期を所有する
- `mobile-command-surface.ts`: 上記を調停し、既存パネルの開閉トリガー、フォーカス、画面プロファイル、公開controller lifecycleを所有する

分割後もブラウザ側の公開入口は `setupMobileCommandSurface()` のままとし、bootstrapやゲーム層へ新しい依存を公開しない。

### 表示状態

表示状態は次の判別可能unionとし、複数の「開いている」変数を並立させない。

- `idle`
- `layer`: `drawer`、`status`、または `quick`
- `panel-pending`: スマホメニューから既存トリガーを呼び、パネルのopen反映を待っている
- `panel-open`: 対象パネルと起点を保持する。起点は `mobile` または `external`

`panel-open(origin=external)` はスマホコマンドが開いたパネルではないため、閉じたときにスマホ入口へフォーカスを奪わず、履歴エントリも操作しない。タイマーhandle、履歴トークン、フォーカス対象はそれぞれ専用controllerが所有し、表示状態にはブラウザオブジェクトを格納しない。

### DOM変更の復元

既存パネルのスマホ装飾はパネル単位のmutation scopeで行う。

- classと属性は初回変更前の有無・値を保存する
- 注入した現在位置、設定ヘッダー、ヘルプ絞り込みボタンはscopeの所有nodeとして追跡する
- listenerも同じscopeへ登録する
- スマホ縦画面から離れたときとcontroller破棄時にscopeを破棄し、既存DOMを変更前へ戻す
- 再度スマホ縦画面へ入りパネルを開いた場合は、新しいscopeとlistenerを作り直す

文書全体を対象とする属性selector削除は行わない。これにより、別機能が同名のdata属性を使った場合も削除対象が拡大しない。

### 初期化

`ui/bootstrap/init-events.ts` の既存イベント登録後に `setupMobileCommandSurface()` を呼ぶ。初期化は冪等にし、必要な既存DOMが欠けてもゲーム起動を止めず、存在する機能だけを表示する。

### メニュー

- `メニュー` 入口を左上safe area内へ固定する。
- ドロワー幅は `min(86vw, 360px)`、高さは `100dvh`。
- 既存機能を `ゲーム` / `コレクション` / `情報` / `設定` に分類する。
- `2Dアクション` は元リンクのURL・安全属性を引き継ぐ。
- 項目選択時はドロワーを閉じてから既存トリガーを実行する。

### 操作シート

- `操作` 入口を右下safe area内へ固定する。
- 既存のリセット、BGM、AUTO、ミュートを代理クリックする。
- BGM選択は既存 `#bgmTrackSelect` のoptionを複製表示し、変更イベントを既存selectへ返す。
- 全体音量は `#seVolSlider` と双方向同期する。
- `リセット` の代理操作ではネット再戦表示を除き確認を出す。ゲーム状態を推測して権威化せず、破壊的操作の確認として扱う。

### 戦況ポップアップ

- `戦況` 入口を右上safe area内へ固定し、`メニュー` と同じ44px以上のタップ領域を確保する。
- 開いたときは `#manifest-effect-panel` と `#stone-info-panel` の実nodeを、参照画像と同じ順でポップアップ内へ一時配置する。テキスト、石一覧、顕現状態を複製・再計算しない。
- 閉じたとき、スマホプロファイルから離れたとき、controllerを破棄したときは、両nodeを元の親・順序へ復元する。
- 閉じるボタン、外側タップ、Escape、ブラウザ戻る、フォーカストラップ／復帰はドロワー・操作シートと同じlayer契約で扱う。
- `#effect-live-panel` はスマホの既存ターン／スコア表示と重複するためポップアップへ移さず、従来どおりスマホ縦画面では非表示とする。

### 敵キャラクターアイコン

- 相手手札行の右端に52px基準の正方形アイコンを置き、手札・山札・盤面へ重ならないグリッド項目として扱う。
- CPU対戦では `#cpu-level-label` の `LvN` と旧スマホ版の実画像 `assets/images/cpu/face/levelN.png` を対応させる。
- ネット対戦など `LvN` でない敵表示では、`#cpu-character-img` の現在画像をそのまま使用する。
- `src`、代替テキスト、ラベル、利用可否だけを対象限定のobserverで同期する。盤面、ゲーム状態、document全体は監視しない。
- アイコン操作は `#cpu-level-label` が利用可能な場合だけ既存CPU・盤面設定入口へ委譲し、`aria-disabled=true` のネット対戦相手表示では設定を開かない。

### 既存パネル

- 設定、見た目、ヘルプ、ランキング、プロフィール、ガチャ、デッキ、ネット対戦、レート戦は、スマホ縦画面で全画面・縦スクロール表示にする。
- 既存の開閉処理と内容DOMは維持する。
- 設定だけは内部閉じるボタンがないため、`#control-panel` にスマホ用ヘッダーを追加し、既存 `#sidePanelToggleBtn` を呼ぶ。
- 既存ヘッダーへ `メニュー / 機能名` の現在位置表示を追加する。
- ヘルプの検索・絞り込みはスマホで折りたたみ可能にし、同一ページ滞在中の状態を保持する。

### 入力、フォーカス、戻る操作

- 開く前のフォーカスを記憶し、閉じた後に入口へ戻す。
- ドロワーと操作シートはTabキーを内部で循環させる。
- 外側タップ、閉じるボタン、Escapeで閉じる。
- スマホ補助レイヤーを開いたときだけ同一URLの履歴エントリを追加し、ブラウザの戻る操作で最上位レイヤーを閉じる。
- 既存パネルをスマホメニューから開いた場合も同じ履歴所有ルールを適用し、パネルを通常の閉じる操作で閉じた場合は所有エントリを消費する。
- 画面プロファイルがスマホ縦画面から外れた場合はスマホレイヤーを閉じ、背景ロックを解除する。

### スタイル

新規 `styles-mobile-command-surface.css` を既存レスポンシブCSSの後に読み込む。

- 適用条件は `html.layout-profile-phone-portrait`
- 既存 `#leftActionButtons` / `#quick-controls-bar` はスマホ縦画面だけ非表示
- 面の基調は現行の濃紺・古金系を維持し、ボタンの左レール、枠、弱い光、アイコンへPC版由来の役割別色を与える
- 役割別色は `emerald`（CPU・戦況）、`azure`（ネット対戦・デッキ・BGM）、`gold`（メニュー・レート戦・ランキング・AUTO）、`ember`（2Dアクション・ガチャ）、`violet`（見た目設定・操作）、`rose`（プロフィール）、`sage`（設定・ヘルプ）、`danger`（リセット）の8種とする
- 色はラベルと既存アイコンを補助する情報として使い、色だけで機能・選択・危険操作を伝えない。フォーカスリングは全色で共通の高コントラスト色、無効状態は彩度と不透明度を下げて操作不能を示す
- 役割色は `MOBILE_COMMANDS` / `MOBILE_QUICK_CONTROLS` の型付き設定へ保持し、描画時に `data-mobile-tone` へ投影する。コマンドIDごとのCSS直書きや別の色設定表は作らない
- タップ領域は44px以上、隣接操作は8px前後の間隔
- `:focus-visible` を明示し、`prefers-reduced-motion` で移動演出を短縮
- ドキュメント横溢れを禁止するが、手札と意図された一覧内スクロールは維持
- 盤面、石情報、カード詳細のスマホ寸法は `styles-responsive.css` を正本とし、コマンドサーフェスCSSから同一selectorの後勝ち上書きを除去する
- `styles-mobile-command-surface.css` は入口、ドロワー、操作シート、戦況ポップアップ、敵アイコン、既存パネルのスマホpresentationだけを所有する

## 互換性・失敗時動作

- PC、iPad、横画面では新ルートを非表示にし、既存UIをそのまま使う。
- JavaScript初期化に必要な個別要素がない場合、その項目だけを生成しない。全体を成功したように見せる代替処理は行わない。
- 既存パネルのトリガーが開かなかった場合は履歴エントリを追加しない。
- DOM監視は対象パネルと代理元コントロールに限定し、盤面更新やゲーム全体を監視しない。
- 戦況表示源が欠ける場合は存在するpanelだけを配置し、敵画像が解決できない場合はアイコンを非表示にする。偽の戦況や代替キャラクターを作らない。
- 同一callbackを使う対象群は1つの `MutationObserver` から複数nodeを監視し、要素数に比例してobserver instanceを増やさない。
- 新規依存関係は追加しない。

## セキュリティ・性能・並行性

- 外部リンクは元の `target` / `rel` / `referrerpolicy` を保持する。
- HTML文字列で外部データを挿入せず、DOM APIと `textContent` を使用する。
- controllerは1回だけ初期化し、イベントリスナーと履歴所有を二重化しない。
- 盤面のcanvas、ticker、ResizeObserver、描画状態へ触れないためSingle Visual Writerと描画性能に影響しない。

## リスクと緩和

- 既存パネルの遅延生成: 初期化時と開く直前の両方でヘッダーを解決する。
- ブラウザ履歴とパネル開閉の競合: 所有トークン付きの単一履歴エントリだけを扱い、所有していない履歴は変更しない。
- DOM装飾の残留: class・属性・node・listenerをパネル単位scopeで復元し、破棄→再初期化を回帰テストする。
- 状態分割による遷移漏れ: 状態遷移を純粋関数へ集約し、`idle` / `layer` / `pending` / `open` の全経路をfocused testで固定する。
- CSS競合: 新規CSSを最後に読み込み、`layout-profile-phone-portrait` へ限定する。
- 古い実装の持ち込み過多: 旧盤面補正、広域アセット同期、HUD／戦況データ複製、広域監視を明示的に対象外とする。
- 戦況nodeのDOM位置残留: 一時配置controllerが元親とnext siblingを保存し、close、profile離脱、destroyの全経路で復元する。

- 既存パネルの遅延生成、履歴競合、画面回転時のロック残留を完了条件と検証対象へ追加した。
- 設計はプレゼンテーション境界内に収まり、ゲーム・盤面・ネットワーク権威を変更しないため、追加の独立レビューは不要と判断した。
- 初回実装後のレビューで、単なるファイル分割だけではARIA残留と再初期化不全を直せないことを確認し、DOM変更scopeを設計へ追加した。
- `activeLayer` と `activePanel` の名前整理だけでは不正な組み合わせが残るため、判別可能unionと純粋遷移へ改めた。
- CSSはファイル数を増やすのではなく、既存のresponsive正本へ重複寸法を戻す最小変更とした。
- 外部起点の既存パネルまでスマホ履歴・フォーカスの所有対象にしないよう、panel stateへoriginを追加した。
- 変更はUI presentation内部に限定され、既存公開API、ゲーム、盤面、ネットワーク契約を変更しない。独立レビューを追加しても境界判断の確度が大きく上がらないため、今回も自己レビューで十分と判断した。
- 追加要望の初案では旧 `mobile-info-panel` のテキスト複製も検討したが、現行の最後使用カード・顕現効果・石一覧との同期経路が二重になるため、既存nodeの一時配置へ修正した。

- 戦況は新しいnative panelではなく既存custom layerの三つ目として扱うことで、相互排他、履歴、フォーカス、背景ロックを同じ状態機械へ集約した。
