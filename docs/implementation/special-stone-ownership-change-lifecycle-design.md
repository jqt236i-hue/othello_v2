# 特殊石の所有権変更ライフサイクル統合 設計

## 問題

`BoardOps.changeAt` は盤面の石色だけを変更し、同じマスにある特殊石・爆弾・石状態の失効や反応を呼出元へ委ねている。通常配置は `clearBombAt` と `clearHyperactiveAtPositions` を後付けで呼ぶため一部だけ正常化されるが、後者は種類の固定リストであり、犠牲石・出稼ぎ石・時間停石などが漏れる。さらに究極反転龍、敵石入替、反転の意志は、復活・屍石・生きる意志の反転後処理を通らない。

その結果、盤面色とマーカー所有者が食い違い、次のような二次障害が発生する。

- 反転済みの犠牲石が後から相手カードを無効化する
- 反転済みの出稼ぎ石を相手特殊石として捕獲できる
- 反転済みの増殖石が破壊時に旧所有者マーカーを残したまま増殖する
- 究極反転龍・敵石入替では復活、屍石、生きる意志が発動しない
- ブラウザ、headless、Worker が同じ不整合な canonical state を共有する

## 対象範囲

- 通常配置、カード反転、龍変換、敵石入替、生成石反転など、`BoardOps.changeAt` を通る実所有権変更
- 特殊石本体、時限爆弾、罠、石状態、盤面マーカー、配置時効果の所有権変更時ポリシー
- 復活・屍石・生きる意志の反転後リアクション
- 意志の反転と禁忌の反転という明示的な所有権移譲例外
- root/browser/headless/local server/Worker mirror の同一挙動

対象外は、石色が変わらない持続終了、破壊、移動、セル消滅そのもの、および見た目だけの preview 状態である。

## 現在の構造

- `shared/special-stone-registry.ts` が特殊石分類、対象可否、反転保護などの正本を持つ。
- `game/logic/board_ops.ts` が canonical な色変更と `CHANGE` presentation event を所有する。
- `game/logic/cards.ts` の `clearHyperactiveAtPositions` が固定種類だけを削除する。
- `game/turn/turn_pipeline_phases.ts` の `applyPostFlipRevives` が通常経路の復活・生きる意志を解決する。
- 龍、敵石入替、反転の意志は独自に `changeAt` を呼び、上記後処理と部分的にしか接続されていない。
- 意志の反転と禁忌の反転は、付帯状態を新所有者へ移譲する既存の明示例外である。出稼ぎ石だけはアンカー喪失を優先して終了する。

## 検討した案

### 案A: 漏れているカード種類を固定リストへ追加する

差分は小さいが、新カード追加時に再発し、龍・入替・反転の意志・復活連鎖の経路差も残る。根本修正にならないため採用しない。

### 案B: 各反転効果モジュールで個別に全マーカーを消す

盤面結果は直せるが、同じ分類規則と例外が複製される。Worker とブラウザのロード境界でも将来ずれやすいため採用しない。

### 案C: レジストリに所有権変更ポリシーを置き、BoardOps と共通後処理を統合する

色変更時の失効を `BoardOps.changeAt` に集約し、反応が必要な効果だけを共通の反転後処理で解決する。特殊な所有権移譲は typed meta で明示する。分類追加時にポリシーを一か所で決められ、全 runtime が同じ root 実装を使えるため採用する。

## 採用設計

### 1. レジストリの所有権変更ポリシー

`StoneEffectRule` に次のポリシーを追加する。

- `revert`: 実所有権変更が成立した時点で付随マーカーを失効し、通常石として扱う
- `resolve_after_change`: マーカーを一時保持し、反転後リアクションで発動・消費する
- `preserve`: 石色変更だけでは状態を失わない

既定値は分類から決める。

| 分類・効果 | ポリシー | 理由 |
| --- | --- | --- |
| 特殊石本体 | `revert` | 実反転後は新色の通常石になる |
| 復活、屍石 | `resolve_after_change` | 元所有者色へ戻す反応を解決する |
| 時限爆弾 | `revert` | 反転で解除する |
| 罠 | `resolve_after_change` | 反転後に罠発動判定が必要 |
| 生きる意志 | `resolve_after_change` | 付与時スナップショットから復活する |
| 毒状態などの石状態 | `preserve` | 毒は反転後も残る。完全保護等は通常反転自体を防ぐ |
| 盤面マーカー・配置時効果 | `preserve` | 石所有権ではなくマスまたは配置解決に属する |
| 顕現石 | `preserve` | 不可侵のため通常は変更されない |

未知の特殊石本体は既定で `revert` とし、新規カードの消し忘れを安全側で防ぐ。

### 2. BoardOps の原子的な正常化

`BoardOps.changeAt` は、保護・幽体判定を通過し、実際に旧色と新色が異なる場合だけ次を同じ操作として行う。

1. 変更前の石IDと特殊石表示メタを保存する
2. `revert` の付随マーカーをレジストリ規則で削除する
3. 出稼ぎ石を削除した場合は `workAnchorPosByPlayer` も同時に解除する
4. 盤面色を変更する
5. 変更前の特殊石表示メタを付けた `CHANGE` を発行する
6. 削除したマーカーの種類を戻り値に含める

削除理由を `reason` の文字列包含判定で推測しない。固定種類リストも使わない。通常の反転音・クロスフェード順を壊さないため、一般の所有権変更失効では追加の `STATUS_REMOVED` を発行せず、既存の `CHANGE` と phase 終了時の出稼ぎ石スナップショット差分を使う。

### 3. 明示的な所有権移譲

`changeAt` の typed meta に `ownershipChangeMode: 'transfer'` を追加する。この mode では `revert` マーカーも自動削除せず、呼出元が既存の `transferCellMarkerOwnership` で所有者・付帯状態を移す。

- 意志の反転: 対象効果と残り状態を移譲する。出稼ぎ石は個別仕様どおりアンカー喪失で終了する。ルール上の反転枚数には含めないため、独立した `countAsFlip: false` も指定する。
- 禁忌の反転: 反転保護を貫通し、付随状態も新色側へ移譲する。復活系リアクションは発火させない。

この内部 meta は presentation payload から除去する。

### 4. 反転後リアクションの共通化

`CardLogic.applyPostFlipRevives` を canonical な共通入口にする。初回反転だけでなく、復活石の起点反転や生きる意志で復活した石の起点反転から生じた追加反転もキューで順に処理し、復活回数や一回限り状態が尽きるまで決定論的に解決する。安全上限に到達した場合は成功扱いで打ち切らず例外にする。

戻り値は従来互換の集約 `regenRes` / `livingWillRes` に加え、`ownerKey`、`source`、順序付き `flips` を持つ `batches` を返す。復活起点の capture flips と生きる意志の `flipped` は、それぞれ変更後の盤面色から次バッチの主体を決める。呼出元は集約結果だけを一度 event/布石へ反映し、各再帰段階で二重加算しない。

TurnPipeline 側の既存 helper はこの API を優先し、互換 mock のみ従来の二段呼出しへフォールバックする。

追加で、現在漏れている経路を接続する。

- 究極反転龍: 配置直後とターン開始の変換結果を同じ後処理へ渡す
- 敵石入替: 実際に `changeAt` が成功した capture だけを返し、詳細 API で後処理を解決する
- 反転の意志: 実反転結果を後処理へ渡す

各経路は復活・生きる意志・復活起点の追加反転を既存の順序で event 化し、保護で変わらなかった座標を反転数や布石に含めない。

## 境界と互換性

- `shared/` は分類データと純粋 getter だけを持ち、盤面やUIを変更しない。
- canonical state の変更は `game/` 内で完結し、DOM、音声、network clientを参照しない。
- UI は既存の `events[]` と presentation events を再生するだけで、マーカー整合性を補正しない。
- Worker/local server/browser/headless は同じ root CardLogic、BoardOps、registry をロードする。
- `applySwapEffect` の boolean API は維持し、詳細結果用 API を追加してTurnPipelineから使用する。
- `clearHyperactiveAtPositions` は互換名として残すが、実所有権変更の成否を判断しない。正常化の正本は `BoardOps.changeAt` だけとし、互換呼出しは冗長 no-op にする。
- 龍と敵石入替の効果モジュールは、注入された BoardOps がない場合も root `BoardOps` を解決して同じ変更契約を通る。canonical runtime で直接 `setCellValue` だけを行う経路を残さない。

## テスト方針

- レジストリ単体: 各分類の `revert` / `resolve_after_change` / `preserve`
- BoardOps単体: reason文字列に依存せず犠牲・時間停石・出稼ぎ・増殖・時限爆弾を削除し、毒を保持する
- 標準配置: 犠牲石が通常石化し、後続カードを無効化しない
- 龍: 特殊石本体の正常化、復活・屍石・生きる意志の発動
- 敵石入替: 実反転だけを返し、復活系を解決する
- 反転の意志: 復活系を解決する
- 連鎖、繁殖・生成石、復活起点 capture、屍石感染、生きる意志復活起点の追加反転: 共通入口を通るか、意図的にリアクション対象外であること
- 例外: 意志の反転と禁忌の反転が付帯状態を移譲し、通常正常化を起こさない
- 意志の反転: `totalFlipCountByPlayer` と角取得数へ加算しない一方、禁忌の反転は通常どおり加算する
- 既存カードの focused Jest、typecheck、TS build、window boundary、network parity
- browser build、Worker asset prepare、mirror consistency

## リスク

- マーカーを消す時点が早まると `CHANGE` の特殊石表示メタが失われるため、必ず削除前に保存する。
- 罠を先に消すと発動できないため `resolve_after_change` とする。
- 毒状態を消すと仕様違反になるため `preserve` とする。
- 復活連鎖は有限状態だが、実装不良による循環を検出する安全上限を設ける。
- 反転後処理の主体色を初回カード使用者へ固定すると、相手側復活から生じた追加反転を誤集計するため、各バッチで変更後の盤面色から再判定する。
- 既存の生成物に別作業差分があるため、source of truth とタスク所有の生成差分だけを分離して扱う。

## 完了条件

- 反転可能な特殊石本体・爆弾が、反転経路を問わず旧所有者マーカーを残さない
- 復活・屍石・生きる意志が、通常配置、龍、敵石入替、反転の意志、追加反転で同じ結果になる
- 罠、毒、意志の反転、禁忌の反転の明示例外が維持される
- root/browser/headless/local server/Worker の契約検証が通る
- focused regression test が二次障害（犠牲の誤無効化、出稼ぎの誤捕獲）まで固定する

## 自己レビュー

- 固定カードリスト追加ではなく、未知の新規特殊石にも適用される分類既定値を選んだ。
- 反転保護、所有権移譲、反転後リアクションを別概念として分離した。
- 罠と毒という「消してはいけない」反例を明示し、一般化し過ぎない設計にした。
- presentation の順序、Worker共有、既存 boolean APIを互換条件へ含めた。
- 回帰試験を状態削除だけでなく、その状態が後から誤発動しないところまで定義した。
