# 森の広場 ふれあい拡張（添い寝・ごはん・遊ぶ・ピアノ・キャラ同士の会話）設計

## 役割と範囲

- 役割: 森の広場に「添い寝」「ごはん」「遊ぶ（ボール・おにごっこ）」「ピアノの演奏」「キャラ同士の会話」を足すための設計と担当境界。
- 対象: `browser-vite/forest-plaza/`（広場の本体コード）、`browser-vite/forest-plaza/lines-data/`（セリフ）、`forest-plaza.html`、`browser-vite/forest-plaza/forest-plaza.css`。
- 正本: プレイヤーに見える仕様は完成後に `01-rulebook.md` の「森の広場」の節へ書く。この文書は実装の設計と分担であり、仕様の正本ではない。
- 範囲外: 新しい GLB 素材の追加（小物は three.js の基本形状で作る）、対局・デッキ・ガチャへの影響、ネット通信、広場の地形・家具の作り直し。

## 方針

- 画面の説明文を増やさない。操作は「手に持つ」「家具を押す」「見ればわかる動き」で伝える。補助ラベルは照準に合わせた時の短い名前（例: `ベッド`）だけ。
- 新しい活動は、キャラが自分から動くもの（ピアノ・会話・おにごっこの誘い）と、プレイヤーが起こすもの（寝る・ごはん・ボール）の両方を持つ。
- 仲良し度（ハート 0〜5）は既存と同じ。新しい活動でも加算し、セリフの態度は段階で変える。
- スマホ（軽い広場・最大3体）でも同じ操作で遊べること。操作はタップとスティックだけで完結させる。
- すべて広場を閉じると破棄され、次に開いた時に引き継がない（仲良し度・時間帯・音のオン/オフだけ保存）。

### 実機実測（2026-10-23、three world座標、m）

経路の実機結果: 中央 `(0,-2)` → ピアノ隣 `(2.25,-8.75)` は29点、ベッド前 `(10,-4.25)` は55点、キッチン横 `(-7.25,-1.5)` は30点。デスクトップ・軽い広場の両方で取得。半径0.3m・他キャラを帰した状態で静的到達性を確認。実際の活動では必ず本人を第3引数へ渡し、その半径で再探索する。大柄なキャラはより離れた到着点を試すこと。

**重要**: ピアノ横 `(2.5,-9.5)` / `(3.25,-7.75)`、ベッドの側面 `(8.5,-6.5)` / `(8.25,-6.5)`、キッチン背面 `(-8.5,-2.75)` は到達不可だった。縁石・支柱・家具と半径が干渉するため、見た目だけで到着点を決めない。ベンチ座面・布団の上は通常経路の到着点にせず、隣接点まで歩いてから姿勢を設置する。ベッドへ移す時は暗転で隠し、起きる時に元の足場へ戻す。

## 共通のしくみ（基盤担当が作る）

### キャラの「指示」操作

`PlazaCharacter`（`characters.ts`）に、活動側から動かすための操作を足す。自動の歩き回りは、活動に占有されている間は止める。

- 占有: `claim(owner)` / `release(owner)` / `isBusy`。占有中は自動で歩き出さない。なでる・あいさつ（`react` / `pet`）は割り込める（割り込んだ時は活動側へ通知して、活動が終わらせる）。
- 移動: 経路を渡して歩かせる（速さ・到着/失敗の通知つき）。
- 姿勢と動き（手続きの動きで表す。GLB に専用アニメは無い）: 立つ・座る（高さを下げる/上げる）・横になる（寝る）・呼吸のゆらぎ・もぐもぐ・はしゃぐ跳ね・リズムに合わせた揺れ・ある点を見る。
- 持ち物の置き場: 口元/頭上/前に小物（食べ物・ボール）を付ける枠。

### 経路探索

敷石の外（ベッド・キッチン・ピアノ）へキャラが歩くための格子経路探索（`activities/pathing.ts`）。既存の `groundAt`（0.25m 格子・家具判定）を使い、必要になった格子だけ調べて A* で経路を作る。幹・家具・段差・プレイヤー・ほかのキャラを避ける。見つからなければ失敗を返す。

### 活動の登録口

`browser-vite/forest-plaza/activities/` に活動ごとのファイルを置き、`activities/index.ts` が一覧にする。`main.ts` の変更は基盤担当だけが行い、活動担当は自分のファイルと、必要なら専用の CSS（活動ファイルから import）だけを触る。

実装済みの契約は `browser-vite/forest-plaza/activities/types.ts`。各担当はひな形の `createSleepActivity(ctx)` / `createFeedActivity(ctx)` / `createBallActivity(ctx)` / `createTagActivity(ctx)` / `createPianoActivity(ctx)` / `createChatActivity(ctx)` の本体だけ実装する。`index.ts` が全 factory を呼び、main が `update(dt秒)` / `dispose()` / `onCharacterRemoved?(character)` / `onCharacterTouched?(character, kind: 'tap' | 'pet')` を配信する。`onCharacterTouched` は通常void（活動を片付けて既存の挨拶/なでへ進む）。おにごっこの捕獲としてクリックを受け取る場合だけtrueを返し、挨拶/なでによる占有解除を止められる。スマホのタップも同じ口へ届く。`pianoSynth.ts` は piano から使う音源モジュールであり、独立した活動ではない。

| API | 実装済みの使い方 |
| --- | --- |
| 基本部品 | `scene`, `camera`, `player`, `renderer`, `visitors`（読取専用Map）, `plaza.root`（ノードを名前で検索）, `isTouch`, `reach`（3.2m） |
| 経路 | `pathing.find(from, to, character?)` → `{x,y,z}[] \| null`。0.25m格子、キャラ半径、家具・幹・段差・他キャラ・プレイヤーを考慮。`pathing.groundAt(x,z)` は静的な床の判定。`walkArea.randomPoint()` は従来の敷石内。動的な障害で歩行失敗したら再探索する |
| 占有 | `character.claim(owner, onInterrupted?)` → boolean。失敗したら始めない。`release(owner)` で経路・姿勢を解除。`isBusy`。`react`/`pet` は割込み通知後に占有を解く |
| 歩行 | `character.walkPath(path, speedMps=1, done?: (arrived:boolean)=>void)`。成功true、障害・置換・解除false。`stopPath(false)`。コールバックは同期する場合があるので状態を先に設定する |
| 姿勢 | `character.setPose({posture:'stand'\|'sit'\|'lie', offsetY?, breathing?, chew?, bounce?, rhythm?})`。offsetYは足元からのm、座ると身長×0.28沈む。rhythmはHz。`setPose({})` で解除。`lookAt(Vector3\|null)`。前はローカル+Z。姿勢は身長に比例する手続き動作。横臥では実際の模型奥行きから求めた `lyingClearance` を自動加算して背中を足場に合わせる（root.position.yは寝床上面を指定）。0.4675mの罠石と1.85mの観測者で横臥の模型下端が床+約0.02mであることを実機確認 |
| 小物枠 | `character.attachments.mouth / overhead / front` はGroup（キャラの大きさで位置を調整済み）。小物の生成・寸法・破棄は活動が管理 |
| 吹き出し | `say(c, situation, {food:'反転りんご',partner:'表示名'})` / `sayText(c,text,ms=2800)`。`spawnHearts(c,count)`, `addAffection(c,amount)`（保存される。段階増加をbooleanで返す）, `hearts(c)`（0〜5） |
| 照準 | `addInteractable({id,label,action,proxy,reach?,enabled?,interact})` → `{dispose()}`。proxyは不可視材質のMesh/Group（Object3D.visibleはtrue）。シーンにまだ親が無ければ追加する。家具本体より少し外へ判定を広げ、家具に遮られないようにする。handleは登録解除だけであり、資源・proxy削除は活動が行う |
| 手持ち | `hand.equip({id,icon:'🍎',model,use({character,direction,point}),onUnequip?})`。一人称の籠手／三人称の右手に同じmodelが移る。modelの原点は手、小さな実寸で作る。対象なしでもuseが呼ばれ、他の操作は遮断。`hand.current`、`hand.equip(null)`。Q/チップでしまった時もonUnequipが呼ばれる。モデルの破棄は所有活動の責任 |
| 寝姿勢 | `player.setPose({position:Vector3,yaw,pitch?,eyeHeight?,lying?,yawLimit?,pitchLimit?})`。移動・ジャンプ停止、見回し制限、三人称の勇者を横にする。`setPose(null)` で元の位置・向きへ戻る。`player.isFixed`。暗転中に呼ぶ。`director.sleeping=true/false` は活動で必ず対にする |
| 入力先取り | `onInput(kind => boolean)`（kindは'move'/'click'）、`onEscape(() => boolean)`。trueで既存操作を消費。登録が新しい順。返された関数で解除。寝起きはこれを使用し、クリックを消費して同時に挨拶しない |
| 暗転・時間 | `await fade(1,0.4)` → 移動 → `await fade(0,0.4)`。`setTime('夜')` は保存しない一時変更、`setTime(null)` は上部ボタンで選んだ時間へ戻す。時間の補間はないので暗転中に切り替える |
| 音 | `audio.context()` / `audio.master` は「歩きはじめる」後だけ取得可能（それ以前null）。全音源はmasterに接続し個別にdestinationへ接続しない。音量初期0.35、♪でミュート。活動は自分のノードを停止・切断する |

手動開始の最小例:
```ts
const owner = {};
function finish() { character.release(owner); /* 小物・音・UIも片付ける */ }
const path = ctx.pathing.find(character.position, goal, character);
if (path && character.claim(owner, finish)) {
  character.walkPath(path, 1.2, arrived => {
    if (!arrived) { finish(); return; }
    character.setPose({ posture: 'sit', breathing: true });
    ctx.say(character, 'listen');
  });
}
```

自動イベント:
```ts
const unregister = ctx.director.register({
  id: 'chat', interval: [40, 70], probability: 0.7,
  participants: 2, maxConcurrent: 2,
  eligible: c => ctx.hearts(c) >= 0,
  start(characters, finish) {
    // 全員がdirectorに占有済み。ここでclaimしない。
    // finishを活動内に保持し、終了・失敗・onCharacterTouched/Removedで呼ぶ。
    // 自分の小物・姿勢などを片付ける処理も同時に行う。
    return true; // falseで開始失敗・占有解除
  },
});
// disposeでunregister()。寝ている間は抽選タイマーも止まる。
```

注意: 自動活動の割込みでdirectorの占有は自動解除されるが、相手の小物・吹き出し・音などの終了は各活動の `onCharacterTouched/Removed` で行う。活動の `dispose` は何度呼ばれても安全にし、非同期の暗転や到着通知が終了後に活動を再開しないよう世代番号などで防ぐ。

### クリックの優先順位

1. 手に持つ物があれば、その物の使い方（ごはんを渡す・ボールを投げる）。使えない時（届かない・キャラを見ていない）は何もせず手に持ったまま。
2. 照準の先の家具・小物（`addInteractable` したもの）。ベッドで寝る・ピアノを頼む・ごはん/ボールを取る。
3. 照準の先のキャラ（既存のあいさつ・長押しでなでる）。

スマホは同じ順で、タップが「クリック」、指を止めたまま長押しが「なでる」。手に持った物は画面下の小さなチップ（物の絵と `×` だけ。文字の説明なし）でしまえる。PC は `Q` でもしまえる。

### 自動イベントの抽選（director）

- ピアノの演奏・キャラ同士の会話・おにごっこの誘いは、`director` が空いているキャラを抽選して始める。同じキャラが二つの活動に同時に入らない。
- 目安: 会話は同時に最大2組、ピアノは同時に1人、おにごっこは同時に1組。プレイヤーが寝ている間は、寝る活動以外の自動イベントを始めない。
- 開始の間隔や確率は各活動の担当が決めて、director に登録する。

### セリフ（`lines.ts`）

追加する場面（`PlazaLineSituation`）。段階つき = ハート 0〜5 の 6 段階（既存と同じ並び）。段階なし = キャラごとに 1 つのリスト（JSON では `[[...]]` の 1 要素）。

| 場面 | 種類 | 使う所 | 本数の目安 |
| --- | --- | --- | --- |
| `sleepIn` | 段階つき | 添い寝に誘われて布団に入る時 | 6 段階 × 6 本 |
| `sleep` | 段階つき | 寝ている間の寝言・寝息 | 6 段階 × 6 本 |
| `wake` | 段階つき | 目が覚めた時 | 6 段階 × 6 本 |
| `eat` | 段階つき | ごはんをもらって食べる時 | 6 段階 × 6 本 |
| `eatFavorite` | 段階つき | 好物をもらった時 | 6 段階 × 6 本 |
| `play` | 段階つき | ボール・おにごっこで遊んでいる時 | 6 段階 × 6 本 |
| `listen` | 段階つき | ピアノの演奏を聴いている時 | 6 段階 × 6 本 |
| `pianoPlay` | 段階なし | 自分がピアノを弾き始める/弾いている時 | 12 本 |
| `chatOpen` | 段階なし | 他のキャラに話しかける | 20 本 |
| `chatReply` | 段階なし | 話しかけられて返す | 20 本 |

- 1 キャラあたり 304 本。キャラごとのファイル（`lines-data/<キー>.json`）の既存キー（`greet` / `pet` / `petMore` / `idle`）はそのまま残し、新しいキーを足す。
- セリフ内の `{food}`（食べ物の名前）と `{partner}`（会話の相手の表示名）は、使う時に置き換える。置き換えられない行は選ばない。`{food}` は `eat` / `eatFavorite` だけ、`{partner}` は `chatOpen` / `chatReply` だけで使える。使うのは全体の 3 割以下。
- 食べ物は `反転りんご` / `執行パン` / `観測おにぎり` / `理論クッキー` の 4 種類（`activities/foodLogic.ts` の `FOODS`）。
- セリフが無い・読めない時のために、`lines.ts` に場面ごとの短い共通セリフ（フォールバック）を持つ。
- 段階なしの場面は、仲良し度によらず常に同じリストから選ぶ（ひとつ前の段階に戻る処理も使わない）。

### セリフの書き方（セリフ担当向け）

- 元の設定は `assets/特殊石のキャラ設定メモ/全特殊石・CPU Lv1-8 性格年齢口調まとめ.md`。キャラの一人称・二人称・語尾・性格は全場面で変えない。
- 段階の態度は既存と同じ: 0 初対面でよそよそしい、1 少し慣れる、2 打ち解ける、3 ツンデレのような照れ・本音、4 デレデレに甘える、5 全面的に信頼してべったり。プレイヤーは「騎士」「リバーシの勇者」など既存セリフでの呼び方に合わせる。
- 内容は健全でかわいい範囲に収める（添い寝は昼寝・お泊まりのような安心感。ぬくもり・寝息・寝相・夢の話・おやすみ/おはよう）。恋愛・性的な表現は使わない。
- 食べる・眠る・弾く・遊ぶが身体的に難しいキャラ（ロボット・幽霊・ゾンビ・竜・神・観測者など）も、そのキャラらしいやり方で自然に書く。
- `chatOpen` / `chatReply` は相手が誰でも通じる内容にする。相手の呼び方は `{partner}` か、そのキャラの二人称。広場の物（木漏れ日・切り株のテーブル・リバーシ盤・ピアノ・ベッド・キッチン・ランタン）や自分の趣味、天気・時間帯、騎士（プレイヤー）の噂は話題にしてよい。`chatReply` は相づち・同意・反論・ツッコミ・聞き返しなど、どんな話しかけにも成り立つ返しにする。
- 1 行は 40 字前後まで。同じ言い回しを別の行・別のキャラで使い回さない。吹き出しに出るので、改行は入れない。

## 活動ごとの仕様

### 1. 添い寝（`activities/sleep.ts`）

- ベッドの照準に `ベッド　クリック：寝る` を出す。押すと、プレイヤーがベッドに横になる（暗転を挟んで 0.8 秒ほどで移る）。
- 添い寝の相手は、広場にいるキャラのうち仲良し度がいちばん高い1体（同点はランダム。経路が無ければ次点）。経路探索でベッドまで歩き、`sleepIn` を言ってプレイヤーの隣に横になる。キャラが大きくてベッドに収まらない時は、枕元に寄りかかって眠る姿勢にする（実測して切り替える）。
- 広場にキャラがいなくてもベッドには寝られる（ひとりで寝る）。
- 寝ている間: 視点は寝た姿勢（天蓋を見上げる向きを基準に、見回しは控えめな範囲だけ）。画面全体をゆっくり夜の明かり（`夜`）に移し、周りを暗くする。寝息のゆらぎ・`z` の記号がふわっと上がる演出。約10秒ごとに相手が `sleep` を言い、約8秒ごとに仲良し度が 1 上がる（1 回の添い寝で最大 +6）。
- 起きる: 移動キー・クリック・タップ・Esc で起きる（Esc は広場を閉じず、起きるだけ）。60 秒たつと自然に目が覚める。相手が `wake` を言い、ハートを出す。時間帯は寝る前に戻る。
- 寝ている間、ほかのキャラは自動イベントを始めない。ほかのキャラに話しかけられたり、なでられたりはしない（寝ている間は照準の操作を止める）。
- 三人称視点でも寝た姿勢の勇者が見える。

### 2. ごはん（`activities/feed.ts`）

- キッチンのテーブルの上に、ゲームモチーフの食べ物を4種類（反転りんご＝赤白の半分ずつ、執行パン＝剣と秤の焼き印、観測おにぎり＝白ごまと光る一つ目の海苔、理論クッキー＝8×8のチョコ格子と黒白の石）置く。三次元の基本形状と手続きテクスチャで、一目でわかる見た目にする。押すと1つ手に取る（取った物はテーブルに残り、何度でも取れる）。
- 手に持つと、一人称では画面右下の手に、三人称では勇者の手に食べ物が見える。
- キャラに照準を合わせて左クリック/タップすると渡せる（届く距離は既存の `REACH`）。渡されたキャラはこちらを向き、食べ物を受け取って約3秒かけて小さくなるまでもぐもぐ（伸び縮み）。食べ終わると `eat` を言い、ハートを出し、仲良し度 +2。
- キャラごとに好物が1つ決まっている（ID から決まる固定の割り当て。観測者＝観測おにぎり、執行者＝執行パン、理論の化身＝理論クッキー、反転の影＝反転りんごだけは名前に合わせて固定）。好物なら `eatFavorite` を言い、ハートがたくさん出て、仲良し度 +5。好物は画面に表示しない（反応で気づく）。
- 食べている間そのキャラは動かない。食べ終わるまで次は渡せない。
- 食べ物を持ったまま、キャラ以外をクリックしても何も起きない。しまうのはチップの `×` か Q。

### 3. 遊ぶ（ボール: `activities/ball.ts`、おにごっこ: `activities/tag.ts`）

ボール:

- 広場のどこか（切り株のテーブルのそば）にボールのかごを置く。押すとボールを1つ手に取る。
- 手に持って左クリック/タップで、照準の向きに放物線で投げる。地面ではずみ、木・家具にはね返り、止まる。投げた物は現在の範囲外（森など）に出たら、数秒後に手元へ戻る。
- 広場にいる空いているキャラ（最大2体、近い順）がボールを追いかけ（走る）、くわえる/頭に乗せるようにして持ち、プレイヤーのところへ戻って足元に置く。置かれたボールは1秒後に手元へ戻る（またすぐ投げられる）。追いかけ始めと戻った時に `play` を言う。戻って来るたびに仲良し度 +1（連続は1キャラにつき5秒に1回まで）。
- 同時に複数のキャラが追いかける時は、いちばん先に届いたキャラが取る。ほかは悔しがる/はしゃぐ動きをして戻る。

おにごっこ（キャラから誘う）:

- 仲良し度がハート1以上のキャラが、プレイヤーの近く（8m 以内）にいる時だけ、ときどき誘ってくる。誘いは「走って近づく → 跳ねて `play`（つかまえてみろ、等）→ 逃げる」。
- 逃げるキャラは、プレイヤーから離れる向きに広場を走って逃げる。プレイヤーが 1.2m 以内でクリック/タップすると「つかまえた」: ハートを出し、役が替わり、今度はキャラが追いかけてくる。追いつかれる（1.0m 以内）と役が戻る。
- 約40秒、または誰かが2回つかまえると終わる。終わりは `play` で満足を言い、ハートを出し、仲良し度 +3。
- 逃げ・追いかけとも経路探索を使い、幹や家具の裏で詰まらない。プレイヤーが誘いを無視して離れれば（16m 以上、または20秒反応なし）自然に終わる。

### 4. ピアノ（`activities/piano.ts`、音は `activities/pianoSynth.ts`）

- 広場にいるキャラが、ときどき自分からピアノのベンチへ歩いて座り、ピアノを弾く。プレイヤーがピアノ/ベンチを押すと、広場にいるキャラのうち仲良し度が最も高い空いた1体が、すぐ弾きに行く（`ピアノ　クリック：弾いてもらう`）。
- 弾いている間: ベンチに座り（高さを調整）、鍵盤の側を向き、曲のリズムに合わせて体を揺らす。ピアノのまわりに音符が舞う。ピアノの補助光（`PianoFill`、普段は消してある）を弱く点ける。弾き始めに `pianoPlay` を言う。
- 音: Web Audio で作るピアノの音（部分音・減衰・やわらかい残響）。曲は短いフレーズを数曲持つ（権利の切れた曲、またはオリジナル。きらきら星・カノン・ジムノペディなど）。音量は広場のピアノからの距離で下げ、左右の位置も反映する。広場を閉じると音も止まる。
- 聴き手: ほかの空いているキャラの一部がピアノの近くへ集まり、ピアノを向いて揺れる。ときどき `listen` を言う。演奏が終わるとはずんで拍手のように跳ね、ハートが出て、演奏者の仲良し度 +2、聴き手 +1。
- 音のオン/オフ: 右上の上部バーにアイコンだけのボタン（♪）を足し、状態を端末に保存する（初期値はオン）。ブラウザが音を許可するのは、広場の「歩きはじめる」を押した後。
- 曲の長さは 40〜70 秒。次の演奏まで 60〜120 秒あける。

### 5. キャラ同士の会話（`activities/chat.ts`）

- 空いているキャラ2体が、ときどき近づいて向かい合い、`chatOpen` と `chatReply` を交互に言う（2〜4往復、1発言 2.4〜3.2 秒）。話しかけた側が最初の発言者。相手の表示名は `{partner}` に入る。
- 会話中は向かい合い（距離はおたがいの半径の和 + 0.5m 前後）、相づちのような小さな跳ね・傾きをつける。ときどきハートや音符など小さな記号が上がる。
- 終わったらそれぞれ元の歩き回りに戻る。同じキャラは次の会話まで 40 秒以上あける。
- なでる・あいさつで割り込まれたキャラは会話を切り上げ、相手も終える。
- 3体以上の輪や、プレイヤーを巻き込む会話は範囲外。

## 担当と進め方

| 担当 | 触る範囲 | 内容 |
| --- | --- | --- |
| 基盤 | `characters.ts`、`main.ts`、`player.ts`、`lines.ts`、`lines-index.ts`、`forest-plaza.html`、`forest-plaza.css`、`activities/types.ts`・`director.ts`・`pathing.ts`・`audio.ts`・`index.ts`、活動のひな形 | 共通のしくみとひな形の登録口 |
| セリフ 1〜5（キャラを9体ずつ） | `lines-data/*.json`（担当キャラの分だけ） | 新しい場面のセリフ |
| 活動A | `activities/sleep.ts` と専用 CSS | 添い寝 |
| 活動B | `activities/feed.ts`、`activities/ball.ts` と専用 CSS | ごはん・ボール（手に持つ物の仕組みを共有） |
| 活動C | `activities/piano.ts`、`activities/pianoSynth.ts` | ピアノ |
| 活動D | `activities/chat.ts`、`activities/tag.ts` | キャラ同士の会話・おにごっこ（自動イベントの仕組みを共有） |

- 同時に動く子は最大4人。基盤とセリフ（最大3人）を先に進め、基盤が終わったら活動A〜Dを進める（セリフが残っていれば空きに入れる）。
- 活動担当が `main.ts` などの共通ファイルに手を入れたい時は、最小の差分に留めて報告に書く（基盤担当は終了済みのため、活動担当が直接直してよい。ただし同時に動く別の活動担当と同じ箇所を触らない）。
- Git の操作（add / commit / stash など）は子は行わない。リーダーがまとめてコミットする。
- `npm run build:vite`、`npm test`（全件）は子は走らせない。確認は `npx vite --port <割り当てのポート> --strictPort --host 127.0.0.1` で `forest-plaza.html?debug=1` を開いて行う。ポートは 基盤 5181、活動A 5182、活動B 5183、活動C 5184、活動D 5185。

## 検証

- 型: `npm run typecheck`（他の担当の作業中のファイルの型エラーは自分の分ではない）。
- 純粋な処理（経路探索・セリフの形式・director の抽選・ボールの物理など）は `test/` に jest のテストを足す。
- 画面: Playwright で `forest-plaza.html?debug=1` を開き、操作と見た目を確かめる（デスクトップ 1920×1080 とスマホ幅の両方）。コンソールエラーが無いこと。
- 音: オフラインレンダリングで無音でないこと・音程が合っていることを確かめる。
- 完成後にリーダーが `npm run build:vite` で通常配信へ反映し、8000 で広場を開いて通しで確認する。
