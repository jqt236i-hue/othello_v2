# ゲーム全体カード比率短縮 設計

## 文書の役割

- 対象: 対局手札、相手手札、カード演出、選択オーバーレイ、天の恵み、デッキ構築に表示する実カード面
- プレイヤー向け仕様の正本: `01-rulebook.md`
- UI寸法の正本: `styles-variables.css` と、端末固有寸法を所有する `styles-responsive.css`
- 非対象: カード詳細本文パネル、ネット対戦roomカード、デッキ保存枠など、名称にcardを含んでもゲームカード面ではないUI

## 問題と目的

初期カード面は標準91x120、手前の手札114x150で、縦横比は約1.32だった。第1調整で横幅を保ったまま `横4:縦5` 前後へ短縮したが、ユーザーの実画面評価では、さらに少し正方形寄りでありながら長方形と分かる形が求められた。

横幅、文字、コスト、カード名、タイプ表示を維持したまま縦方向だけをもう一段短くし、正方形ではない `横5:縦6` 前後へ統一する。PCだけ、またはスマホだけの局所変更にはしない。

## 要求・前提・制約

- 「幅を縮める」はユーザーの先行表現である「縦幅を削減」を指すものとし、横幅は変更しない。
- カード面は正方形にせず、縦長の五角形フレームを維持する。
- 文字サイズ、バッジサイズ、タップ・クリック挙動、カード枚数、手札スクロール方式は変更しない。
- ゲームルール、カード効果、状態、盤面描画、ネットワーク契約は変更しない。
- `worker-public/` は生成mirrorであり、root CSS変更後に既存スクリプトで同期する。

## 現行構造と調査結果

- `.card-item`、飛行カード、保持カード、天の恵み候補は `--layout-size-card-width/height` を共有する。
- 自分手札は `--layout-size-card-large-width/height` を共有する。
- `layout-profile-phone-portrait`、iPad縦、低幅横画面には `styles-responsive.css` の直接寸法がある。
- デッキ構築カードは `.card-item` を再利用し、追加操作のため `標準カード高 + 20px` の最小高を持つ。
- カード詳細パネルはカード面ではなく説明UIなので比率変更の対象外である。

## 選択肢

### 高さへ一律係数を掛ける

既存の比率差を残すため、端末ごとに見た目が揃わない。カード高の正本も分散したままになるため採用しない。

### `aspect-ratio` だけを指定する

既存の明示 `height` と競合し、手札・アニメーション・デッキ構築の確定寸法を曖昧にする。Stage scaleと端末固有寸法の契約も弱めるため採用しない。

### 各既存寸法を横5:縦6へ丸める

横幅と既存レイアウト契約を保ち、縦方向だけを予測可能に短縮できる。カード種別を問わず同じ視覚言語になり、既存のStage scale経路も維持できるため採用する。

## 採用寸法

| Surface | Before | After | After ratio (height / width) |
| --- | ---: | ---: | ---: |
| 標準カード | 91x114 | 91x109 | 1.198 |
| 自分手札・標準large | 114x143 | 114x137 | 1.202 |
| tablet large | 112x140 | 112x134 | 1.196 |
| スマホ相手手札 | 61x76 | 61x73 | 1.197 |
| スマホ自分手札 | 92x115 | 92x110 | 1.196 |
| iPad縦の自分手札 | 88x110 | 88x106 | 1.205 |
| 小型横画面の自分手札 | 96x120 | 96x115 | 1.198 |

デッキ構築カードは操作用フッター20px相当を必要とするため、`標準カード高 + 20px` を最小高とする。これにより標準カード109px時は129pxとなり、共通カード高の将来変更にも追従する。

## 所有境界とデータフロー

- `styles-variables.css` が標準・large・tablet largeの高さを所有する。
- `styles-responsive.css` がスマホ、iPad縦、小型横画面のカード高だけを所有する。
- `styles-feature-deck-builder.css` は共通カード高に加える操作領域だけを所有する。
- `styles-cards.css`、カードrenderer、アニメーションは既存変数を消費し、別の比率定数を持たない。

## 互換性・失敗時動作

- 横幅、DOM構造、selector、公開APIを変えないため、カード選択座標・手札scroll・アニメーションgeometryは描画後の実矩形へ自然に追従する。
- CSS変数が利用できない環境への新しいfallbackは追加しない。既存ランタイム前提と同じである。
- 文字が収まらない場合に文字をさらに縮小するfallbackは追加しない。QAで長いカード名と特殊カードを確認し、必要なら内部余白だけを調整する。

## アクセシビリティ・性能

- 文字サイズ、色、コントラスト、フォーカス、操作領域は変更しない。
- スマホの手札は引き続き意図された横スクロール領域とし、ページ横溢れは増やさない。
- CSS寸法だけの変更で、新規observer、タイマー、画像、依存関係は追加しない。

## 検証戦略

- CSS contract testで標準・large・各responsive寸法が横5:縦6前後であることを固定する。
- 既存のhand/deck scale、responsive、天の恵み、デッキ構築CSSテストを実行する。
- `npm run typecheck`、`npm run checkall`、`npm run build:browser`、`npm run worker:prepare` を実行する。
- 実ブラウザで1280x720 PCと393x852スマホを比較し、自分カードの実矩形、文字欠け、敵カード、ページ横溢れを確認する。
- デッキ構築画面を開き、候補カードと詳細ボタンが縦方向に欠けないことを確認する。

## リスクと緩和

- 特殊カード立ち絵や名前plateの縦方向衝突: 文字・バッジを縮小せず実画面で特殊カードを含むカード面を確認する。
- 端末別overrideの更新漏れ: 直接カード高を持つ全selectorをcontract testへ列挙する。
- デッキ構築の操作領域不足: 共通高へ20px reserveを加える式とし、固定の旧カード高へ依存させない。
- 生成mirrorの不一致: rootのみ編集し、`worker:prepare` とmirror checkで同期する。

## 完了条件

- 全カード面の横幅は変更前と同じである。
- 標準・large・全responsive救済のカード高が表の値になり、長方形のまま横5:縦6前後へ揃う。
- 飛行、保持、天の恵みは共通変数を通じて新比率になる。
- デッキ構築カードは新しい共通高に追従し、操作内容が欠けない。
- PC・スマホで文字、コスト、カード名、タイプ、カード画像が読める。
- ページ横溢れ、手札外へのバッジ欠け、既存操作回帰がない。
- 仕様、設計、計画、root実装、生成mirrorが一致し、検証済み差分がコミットされる。

## Self-review

- 初案では `styles-variables.css` の2変数だけを変更する想定だったが、スマホ・iPad縦・小型横画面に直接カード高があり、デッキ構築には旧高依存の `min-height` があるため対象へ追加した。
- `aspect-ratio` の一括指定は既存の確定サイズ契約を曖昧にするため、Stage scaleへ乗る基準値を更新する方式へ修正した。
- 第1調整の4:5は実装・検証済みだったが、ユーザーの追加評価を新しい表示仕様として優先し、もう一段だけ正方形寄りの5:6へ更新した。5:6は高さが幅より約20%大きく、正方形ではない縦長を数値上も維持する。
- 各寸法は幅から5:6へ整数丸めし、比率許容を1.19〜1.21へ限定する。文字や操作を縮小する方法は採用しない。
- 変更はpresentation寸法だけで、ゲーム・盤面・ネットワーク権威や公開APIへ触れない。既存のCSS contract coverageも豊富なため、独立レビューは追加せず自己レビューで十分と判断した。
