# PixiJS 盤面移行実装計画

- Status: proposed
- Design: `docs/implementation/pixijs-playfield-migration-design.md`
- Date: 2026-07-14
- Execution mode: behavior-preserving な直列 phase。各 phase を focused verification 後に task-owned files だけで commit する
- Player-visible specification: 原則変更なし。表示・入力・演出時間・対応条件を変更する必要が生じた場合は実装を止め、`01-rulebook.md` と該当 `正本/*.md` を先に更新する
- Final boundary: 通常の盤面/石/盤面内演出は PixiJS、カード/HUD/フォーム/文字 UI と装飾フレームは DOM。WebGL init/recovery failure だけは isolated DOM board compatibility backend

## 実行原則

1. Phase 0～3 は production の DOM 盤面を変えず、移行 seam と baseline を先に固定する。
2. Phase 4～8 の Pixi backend は `?debug=1&boardRenderer=pixi` または test harness injection でだけ有効にする。
3. DOM/Pixi backend は常に排他的に mount し、比較目的でも同一ページで同時更新しない。
4. phase の Done when を満たさないまま次へ進まない。特に animation event の silent fallback と visual baseline の一括上書きを禁止する。
5. root source を変更してから `npm run build:browser`、必要な時点で `npm run worker:prepare` を実行し、`public/`、`vite-dist/`、`worker-public/` を source-edit しない。
6. `game/`、`shared/`、CPU、Worker に PixiJS dependency を持ち込まない。
7. 長い selfplay/training は実行しない。
8. 各 phase の開始時と commit 前後に `git status --short` を確認し、別作業の dirty files があればその phase を開始しない。
9. 各 phase の focused verification 後、commit 前に `git diff --check` を必ず実行する。

### Work

1. `dependencies` に `"pixi.js": "8.18.1"` を完全固定で追加し、lockfile を更新する。移行中に version range を広げない。
2. `prepare-pixi-classic-assets.ts` は `node_modules/pixi.js/dist/pixi.min.js` の存在、package version、非空/expected banner または content hash を検証してから `public/vendor/pixi-8.18.1.min.js` を生成する。
3. `build:browser` の `build:ts` 後、module registry 生成前に classic vendor 生成を実行する。
4. `index.classic.html` で vendor を `entry-browser.js` より前に読む。CDN fallback は追加しない。
5. `UIBootstrap.configurePixiRuntime(runtime)` を idempotent な注入境界として追加する。Pixi object を `game/` や canonical state に渡さない。
6. Vite lane は `browser-vite/main.ts` が catch 可能な dynamic import を boot promise の先頭で行い、成功時だけ既存 `beforeInitialize` で runtime を注入する。chunk load/preload failure は capability reason を残して app boot/DOM fallback を続ける。
7. classic lane は local vendor script の load failure 後も app entry を続行し、bootstrap 境界だけが `window.PIXI` を読み、成功時に同じ runtime contract へ注入する。missing global は DOM fallback reason とする。
8. runtime capability は version、injected/not-injected、lane だけを read-only で保持する。この phase では `Application` を作成しない。
9. Worker mirror の explicit root files に local vendor を追加し、mirror test で drift/missing を検出する。

4. `BoardRenderInputs` を `baseVisualState` と `presentationOverlayState` に分離する。network base は visual-state-store だけから取り、hover/keyboard/preview/direction/local pending hint/lock は後段 overlay として合成し、base cell/stone/accepted marker/pending outcome を変更できないよう validator で制限する。

6. `BoardVisualController` に `idle`、`playback`、`awaiting-frame-commit`、`recovering`、pending-latest visual frame、backend lifecycle を実装する。これは board-writer substate に限定し、busy/input/selection/queue authority は `PlaybackStateManager` に残す。
7. 同一 run/frame token で `PlaybackStateManager.begin/claim → controller.claimWriter → dispatch → final/committed sync → controller.releaseWriter → manager.finalize` の順を contract test に固定する。recovery/error 中は manager lock を早期解除せず、selection settlement lock を持ったまま idle を待たない。
8. `DomBoardVisualBackend` が既存 `initializeBoardDOM()`、`renderBoardDiff()`、cell lookup を包み、上位 caller は controller だけを呼ぶようにする。
9. `ui/board-renderer.ts` に混在する time-stop BGM/body class、manifest background/panel の同期を `world-state-presenter.ts` へ分離する。render model builder に DOM/sound side effect を残さない。
10. `frame-presenter.ts` に frame skin/layout、`board-has-void-cells`、game-container oversize class の同期を置き、cell/stone writer から分離する。playback 中は controller が通常 model の frame 更新を defer する。
11. `render-scheduler.ts` は model を一度作り、controller と card/status scheduler へ明示的に渡す。playback 中の defer は controller 一箇所に集約する。
12. `?debug=1`/test flag 限定の diagnostics contract を作る。この phase の backend kind は `dom` だけでよい。
13. 既存 DOM backend の HTML、class、pixel、入力を変えず、Phase 0 digest を完全一致させる。

### Work

1. `Application` を design 固定値で async init し、`#board` に canvas を一枚だけ mount する。`#board-frame` と `#card-fx-layer` は DOM のままとする。
2. controller が `data-board-renderer` を設定し、Pixi lane では `#board` の旧 surface/grid/pseudo-element を CSS で無効化する。DOM frame art/layout は維持する。
3. scene graph を surface → cell → marker → stone → hint → playback → effect → interaction の固定順で作る。
4. `#board-scroll-viewport` と cell DOM を持たない `#board-scroll-surface` を作り、Pixi camera/canvas は可視 viewport、前後1セルの object overscan、各辺最大2セルの effect gutter だけを描く。canvas backing store を全 logical board size まで拡大しない。
5. 可視 world coordinate key ごとに retained view を保持し、model signature が変わった object だけ更新する。offscreen view は pool へ戻す。
6. 上/左拡張では追加行/列の physical size 分を logical origin と scroll offset に同一 frame で加え、下/右では origin を維持する。全方向で既存セルの client rect と対局開始時 cell size を不変にする。
7. 4～16 の可変長方形、circle、hole、void、上下左右の多段 expansion、negative coordinate、viewer context を描画する。
8. default/special stone、timer/badge/marker、合法・選択・対象・preview・keyboard cursor の静止画を実装する。
9. effect family の bounds manifest を作り、2セル gutter 内の board-local effect と、それを超えて DOM global presenter に残す effect を固定する。
10. board/stone runtime が catalog/storage 由来の appearance descriptor を返すようにし、Pixi が CSS `url(...)` を解析しないようにする。
11. `styles-board.css` の盤面 visual 値を semantic CSS custom property に整理し、theme resolver が検証済み color/number/font descriptor を作る。DOM/Pixi は同じ descriptor を使う。
12. 選択 font の変更と `document.fonts.ready` 後に theme revision を更新し、board bonus、timer、方向 hint を再描画する。double-digit sizing と shadow/glow を fixture 化する。
13. catalog の相対 path を `document.baseURI` 基準で absolute URL 化し、built-in/custom Blob texture の preload、atomic swap、default/procedural fallback、lease/release/destroy を実装する。Vite chunk URL を asset base にしない。custom skin 原本は保持し、表示先の最大 physical pixel size と WebGL `MAX_TEXTURE_SIZE` 以下へ縦横比を保って downsample した派生 bitmap だけを upload する。
14. playback/recovery 中の skin/theme/font change は resource 準備だけを行い、final/committed sync で latest descriptor を一回 atomic apply する。
15. `ResizeObserver` と `visualViewport` resize/scroll/scale/offset で layout/camera を更新し、DPR を 2 で cap する。browser/pinch zoom を相殺しない。
16. static phase では `?debug=1&boardRenderer=pixi&noanim=1` のみ許可し、normal animation の live play は capability error で止める。
17. idle settle 後に ticker と rAF が止まることを diagnostics で証明する。
18. bootstrap は controller `ready` を await してから board input、network activation、app-ready signal を有効にし、準備中の render request は initial latest visual frame 一件へ集約する。

### Work

1. 現行 interaction-binder の pointer/hover/long-press、pointer move cancel、direction、lock state を backend-neutral controller へ移す。overflow 時の wheel/touch pan は scroll viewport を動かし、gameplay swipe action を新設しない。
2. DOM backend と Pixi `interactionLayer` が同じ normalized input event を controller へ送る。
3. Pixi `eventMode`/`hitArea` は render model の playable/interaction state だけから作り、合法性を計算しない。
4. `game-keyboard-shortcuts.ts` の `.cell.legal` query を model controller の sorted legal cells に置換し、現行 row/col tie-break を固定する。
5. keyboard cursor は `presentationOverlayState.keyboardCursorKey` を更新して model 再投影から hint layer に描画し、backend への第二の direct cursor setter を作らない。Space の placement は既存 `handleCellClick` を呼ぶ。
6. 方向ヒント用 semantic button を `#board` 内の accessibility layer に作り、現行 `role`、focus、`aria-label`、Enter/Space activation を維持する。
7. semantic button の focus/blur を Pixi の visible focus ring と同期し、canvas は `aria-hidden="true"` にして操作を二重公開しない。
8. modal open、playback、pending selection、spectator の lock を既存 state から注入し、Pixi view の状態から推測しない。
9. E2E の board click は diagnostics の client rect 中央を実 pointer で押す。直接 handler 呼び出しだけで input 成功扱いにしない。

2. accepted frames、late frame、self-publish response/stream race、reconnect、spectator、pending selection reconcile を Pixi playback/controller で通す。
3. playback 中の同一 active presentation frame に属する重複 render request は pending latest visual frame に集約する。board phase 完了後は event 最終表示を保持して `awaiting-frame-commit` へ移り、`dispatchFrame()` を返す。timeline が `visualStateStore.commitFrame()` した後の必須 `applyCommittedFrame` hook で committed state/overlay/layout/appearance/theme を一つの visual frame にし、一回 full sync する。hook 成功後にだけ `visualSettlementTracker.markVisualSeqCompleted()` を呼び、observer、writer release、manager finalize の順で完了する。別々の accepted frame は順番どおり残し、coalescing しない。
4. `applyCommittedFrame` を best-effort callback と分離して timeline が await する。現行の同期 `markFramePlayed()` は廃止するか `Promise<boolean>` に変え、`drainPlayableFrames()` と同じ `commitFrame()` →必須 hook → tracker 完了 → observer の settlement 経路へ統合する。fire-and-forget で `notifyFrameCommitted()` を呼ぶ commit 経路は残さない。失敗時は timeline/input を pause し、event を再発火せず committed store から model apply を retry する。hook 成功前は tracker を未完了に保ち、writer/manager claim を解放せず、次 frame を dispatch しない。
5. strict-network 成功時は `presentation-handler.ts` の `finally` で playback claim を release せず、`playback-dispatcher.ts` が opaque settlement handle を timeline へ返す。timeline は required committed-frame sync、tracker、observer が終わった後にその handle で writer release/manager finalize を一度だけ行う。local playback と handoff 前の例外は presentation handler が解放し、hook retry/context recovery は handle を保持する。typed result、所有権移転、idempotent release を contract test で固定する。
6. 各 board phase の pre-phase model、events、board visual completion を checkpoint する。`webglcontextlost` で input/settlement を lock し、restore 後に texture reload → pre-phase model restore → active board visual phase replay → queue resume の順で復旧する。
7. loss が `awaiting-frame-commit` 中なら event を再生せず、commit 後の model apply だけを restored/fallback backend で retry する。
8. recovery replay では sound/log/DOM global effect を再発火せず、accepted frame を phase success 前に dequeue しない。5 秒で Pixi 復旧しなければ DOM compatibility backend を単独 mount して同じ checkpoint/phase を再生し、両backend失敗時だけ reload-required error にする。event success や command retryを捏造しない。
9. browser tests の `.cell`/`.disc`/`forceFullRender` dependency を gated diagnostics、client rect、model/rendered digest へ移す。
10. visual harness は canvas render idle を待って `#board` を capture する。
11. selector inventory check を `checkall` または focused script に追加し、default/Pixi browser test code に盤面 DOM selector が再導入されたら fail させる。DOM backend の focused unit/forced-fallback test は明示 allowlist に限定し、Phase 10 で compatibility suite 名へ移す。
