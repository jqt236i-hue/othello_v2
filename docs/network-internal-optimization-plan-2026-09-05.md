# ネット対戦の内部最適化計画

役割: 実装・検証の進捗記録。対象はネット対戦の保存、履歴、通信、クライアント状態管理。正本は `architecture-contracts.md`。ルール、表示、演出順・時間・音、入力再開条件、履歴保持数、非公開情報、再送保証は変更しない。本番デプロイと別作業の訓練停止は対象外。

## フェーズと完了条件

1. 保存: 現在状態と履歴を分離し、変更分だけを同一transactionで保存。旧保存形式の読み込み、失敗時の原子性、再構築、履歴上限と削除を検証。
2. コピー: 所有権が確立された変更不可履歴だけを再利用し、公開projectionの権限境界を維持。入力の後続変更、返却値の変更が履歴に影響しないことを検証。
3. 通信: 旧形式/V2を維持し、明示対応する新クライアントへの可逆的な演出データ圧縮を追加。完全復元、破損拒否、権限、HTTP/SSE一致を検証。
4. UI内部: 状態コピー再利用、タイマーの隣接重複通知、同一観戦payloadのエンコードを削減。演出やタイミングを維持。
5. 検証・配信: focused tests、network parity、型、Worker同期、実ブラウザの対戦/観戦/再接続、性能前後比較。最終build:vite、8000の所有者・継続稼働・HTTP 200を確認し、今回分のみコミット。

## 検証の前提

既存調査は `artifacts/network-audit-20260905/findings.md`。性能比較は履歴8件の条件で変更なし保存と新規履歴追加を分け、保存代替だけの時間を本番保存時間と呼ばない。空・少数・上限の履歴は保存契約テストでも確認する。端末上の別訓練との競合を記録する。物理スマホや本番の未検証範囲は明記する。
