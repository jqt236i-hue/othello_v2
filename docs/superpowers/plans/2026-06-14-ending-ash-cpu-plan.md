# Ending Ash CPU Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new `Lv8: 終焉の冥灰` CPU opponent that reuses the existing Lv6+ move, pending-placement, and card-use decision logic, starts with 99 charge, unlocks card use from turn 6, and uses the fixed deck supplied in the request.

**Architecture:** Treat this as a CPU opponent profile and deck preset addition, not a new card or a new AI policy. The new profile uses `level: 8` for display/profile selection and `decisionLevel: 6` for gameplay decisions, so existing Lv6+ normal placement, pending target, and card-use paths stay shared. Startup options provide the fixed deck, initial charge, and card-use unlock turn through the existing `CpuOpponentProfiles` and `CpuOpponentStartupOptions` boundary.

**Tech Stack:** TypeScript/CommonJS modules, Jest, existing deck codec helpers, existing browser module registry build, existing worker asset preparation.

---

## Assumptions

- Display level is `Lv8` because the request says `レベル?CPU` and the requested handicap is stronger than `Lv7: 理論の化身`.
- Profile id is `8-ending-ash`.
- Display name is `終焉の冥灰`.
- Portrait path is `assets/images/special-cards/characters/終焉の冥灰.png`; the file already exists and is already present in `assets/asset-manifest.json`.
- Gameplay decision level remains `6`, so normal placement, pending placement, hand-destroy cycling, and card-use logic reuse the current Lv6+ code.
- No `正本/` update is needed because this does not change card behavior, target rules, turn order, animation, or sound. `01-rulebook.md` must be updated because this is player-visible CPU/deck/startup behavior.
