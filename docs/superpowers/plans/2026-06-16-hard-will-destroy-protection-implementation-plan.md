# Hard Will Destroy Protection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `硬い意志` as a cost-4 card that gives one own board stone an 8-owner-turn `破壊保護` stone status.

**Architecture:** Use the existing pending-selection bridge and `guardTarget` payload shape so network and UI dispatch stay aligned with the current guard-like flow. Represent the new protection as registry-backed stone status `DESTROY_PROTECTION`, letting `BoardOps.destroyAt` block destruction through `destroyProtected: true` while all non-destroy effects continue through their existing paths. Keep canonical rule logic in `game/`, display text in `cards/` and rule/help surfaces, and update generated catalog/browser/worker mirrors only through scripts.

**Tech Stack:** TypeScript/CommonJS-compatible modules, Jest, generated card catalogs, browser module registry build, Cloudflare Worker public mirror sync, and focused network/worker validation.

---

## Product Decisions Locked For This Plan

- Card display name: `硬い意志`
- `cardId`: `hard_will_01`
- `type`: `HARD_WILL`
- Stone status marker type: `DESTROY_PROTECTION`
- Cost: `4`
- Duration: `8` owner turns
- Target: one occupied board-shape cell containing the current player's stone, same target set as `getGuardTargets`
- Reapply behavior: refresh the current player's `DESTROY_PROTECTION` marker on that cell to `8`, not stack
- `延命の意志` / `延命神`: can multiply this status because it is a stone status with `remainingOwnerTurns`
- `腐食の意志`: can halve this status unless the cell is fully protected by `GUARD`
- `意志の喪失`: does not remove this status because stone statuses are outside `LOSS_WILL`
- Stops: stone destruction and explosion because explosion is a destruction effect
- Does not stop: flip, exchange, movement, temptation, capture, corrosion, loss, freeze, teleport, cell removal, hole creation, board shrink, and other non-destroy effects
- Destroy target lists exclude destroy-protected stones. If a low-level path forces `BoardOps.destroyAt`, it returns `{ destroyed: false, reason: 'destroy_protected' }`.
- No `stone_destroy` sound or destroy fade is emitted for a destroy-protected no-op. Selection success uses the existing self-stone selection sound path.

function applyHardWill(cardState: CardState, gameState: GameState, playerKey: PlayerKey, row: number, col: number, deps: any): Record<string, any> {
    const readCardPendingEffect = deps && deps.readCardPendingEffect;
    const getGuardTargets = deps && deps.getGuardTargets;
    const removeMarkersAt = deps && deps.removeMarkersAt;
    const addMarker = deps && deps.addMarker;
    const clearCardPendingEffect = deps && deps.clearCardPendingEffect;
    const MARKER_KINDS = deps && deps.MARKER_KINDS;

    if (
        typeof readCardPendingEffect !== 'function' ||
        typeof getGuardTargets !== 'function' ||
        typeof removeMarkersAt !== 'function' ||
        typeof addMarker !== 'function' ||
        typeof clearCardPendingEffect !== 'function'
    ) {
        return { applied: false, reason: 'deps_missing' };
    }

    const pending = readCardPendingEffect(cardState, playerKey);
    if (!pending || pending.type !== 'HARD_WILL' || pending.stage !== 'selectTarget') {
        return { applied: false, reason: 'not_pending' };
    }
    const targets = getGuardTargets(cardState, gameState, playerKey);
    const allowed = targets.some((target: any) => target.row === row && target.col === col);
    if (!allowed) return { applied: false, reason: 'invalid_target' };

    const remainingOwnerTurns = deps.HARD_WILL_TURNS || DEFAULT_HARD_WILL_TURNS;
    removeMarkersAt(cardState, row, col, {
        kind: MARKER_KINDS ? MARKER_KINDS.SPECIAL_STONE : 'specialStone',
        type: 'DESTROY_PROTECTION',
