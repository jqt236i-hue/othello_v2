# 犠牲の意志 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the browser card-reversi card `犠牲の意志` as a cost 14 normal card that turns the next placed own stone into a 5-turn `犠牲石`; while that stone is on the board, the opponent's next normal card use is accepted, consumed, visually burned, nullified, and then the sacrifice stone destroys itself. Special cards are excluded and resolve normally.

**Architecture:** Keep the rule in headless card logic. `applyCardUsage` remains the single card-use gate: after normal card consumption and before pending/immediate effects are written, it asks a small `SACRIFICE` helper whether an opponent-owned sacrifice stone should intercept the card. The helper mutates only canonical game/card state and emits ordered presentation events. Browser UI only maps those events to existing playback plus one lightweight card burn variant. No DOM, timers, sound, or network access enters `game/`, `shared/`, CPU logic, or pure card logic.

**Tech Stack:** TypeScript/CommonJS hybrid modules, `cards/catalog.json` plus generated catalog files, Jest focused tests, existing animation playback events, Cloudflare Worker mirror generated by `npm run worker:prepare`.

## 決定仕様

- Card id: `sacrifice_will_01`
- Card type: `SACRIFICE_WILL`
- Display name: `犠牲の意志`
- Cost: `14`
- Display category: `特殊石`
- Marker type: `SACRIFICE`
- Marker display name: `犠牲石`
- Duration: `5` owner turns
- Card effect: next own placed stone becomes `SACRIFICE`.
- Trigger condition: a `SACRIFICE` marker owned by the opponent of the card user exists on an occupied board cell.
- Exclusion: `shared/special-card-registry.ts` special cards bypass the trigger and resolve normally.
- Card-use outcome when nullified:
  - `applyCardUsage` returns `true`.
  - The used card leaves hand, enters discard, pays cost, updates `hasUsedCardThisTurnByPlayer`, `cardUseCountByPlayer`, and `lastUsedCardByPlayer`.
  - No pending target selection is created.
  - No immediate effect from the nullified card is applied.
  - The sacrifice stone is destroyed by the existing `BoardOps.destroyAt` path with cause `SACRIFICE_WILL` and reason `card_nullified`.
  - The log line is exactly `犠牲の意志がカードを無効化`.
- Multiple sacrifice stones: choose the oldest deterministic marker: lowest finite `createdSeq`, then lowest finite numeric `id`, then row, then col.
- Duration expiry: if no card was nullified before its timer ends, the `SACRIFICE` marker expires through the existing timed special-stone `duration_end` path and the underlying stone remains as a normal stone.
- Trigger destruction: when the effect nullifies a card, the stone itself is destroyed and the cell becomes empty through the normal destroy path.
- Stone art: sacrifice stone images are available at `assets/images/special-stones/SACRIFICE_WILL-black.png` and `assets/images/special-stones/SACRIFICE_WILL-white.png`. Wire these paths when adding the `SACRIFICE` visual effect map entry. Do not rename them again, and do not edit `worker-public/` assets by hand.
- Placement speech: `この石が、次の意志を引き受ける。`
- Effect speech: `その一手は、ここで断つ。`
- Duration-expiry speech: `役目を待たず、意志は静かに尽きた。`

## Playback Contract

Playback order for a nullified normal card:

1. Opponent uses a card.
2. Existing card-use pickup animation plays.
3. The lifted card uses the new `sacrifice_seal_burn` disappearance variant: red tint, short seal/noise crackle, red glow, fade out.
4. After the lifted card disappears, the board sacrifice stone runs the existing red-highlight destroy/fade playback from the canonical `DESTROY` event.
5. The log shows `犠牲の意志がカードを無効化`.

The stone destroy animation is not new work. Reuse existing `DESTROY` playback and existing board writer flow.
