## 固定した設定と公平性

| 対象 | 判断バージョン | 最大遷移 | 時間上限 |
| --- | --- | ---: | ---: |
| 採用Lv11 | `lv11-sparse-endgame-dev5` | 4,096 | 4,800ms |
| 開始時保存Lv10 | `lv10-canonical-beam-dev7` | 1,024 | 1,500ms |

両者とも同じ93枚デッキ、同じ6種類の除外、初期布石99・上限99・獲得倍率2倍・カード解禁 `turnNumber >= 6`。Lv10の保存先は `data/cpu-lv11/baseline-start/repo`、採用候補は `data/cpu-lv11/candidates/dev5/repo`。対局条件は配布時に固定し、CPUは通常の公開観測のみを受け取る。実際の相手の未公開手札・山札順・未来乱数は渡さない。探索予算はそれぞれの本番設定であり、同一予算の比較ではない。

Lv11では疎な盤面の終局接近、相手の応手、自石消滅リスク、継続効果・手札を残す価値を改善した。通常画面に組み込んだ探索・評価JSは保存候補とハッシュ一致し、設定も一致する。`data/cpu-lv11/dev5-adoption-policy-identity-v1.json` を参照。開始時Lv10の保存内容は変更していない。

## 再現とビルド

プロジェクト直下でビルドした後、保存した行動列と固定ランタイムを再監査できる。出力ファイル名は未使用名にする。

```powershell
npm run build:ts
node dist/scripts/audit-cpu-experiment.js data/cpu-lv11/lv11-dev5-sparse-endgame-acceptance-30-v1 data/cpu-lv11/audit-repeat.json
node dist/scripts/inspect-production-decision.js data/cpu-lv11/lv11-dev5-sparse-endgame-acceptance-30-v1/games/4-white/attempt-1 1 data/cpu-lv11/decision-repeat.json
```

保存された行動・状態の再生は照合できる。実時間で打ち切る探索の再実行は同じseedだけで同一行動を保証しない。採用に使用済みの条件は新たな採用評価へ流用しない。大容量の保存ランタイム・対局ログ・画像証拠はローカルの `data/cpu-lv11/` に保持し、コミットには含めない。

関連テスト111件、型検査、最終Viteビルド、通常配信のmirror同期検査が成功。最終表示変更の型付きビルドと表示検証も成功。記録は `dev5-adoption-*-tests-v1.log`、`dev5-adoption-leaderboard-ui-v2.log`、`dev5-final-typecheck-v1.log`、`dev5-final-name-build-v1.log`、`dev5-final-mirror-check-v1.log` など。

別作業の変更を除いたソースでもViteビルド・同期を実施し、その生成物を今回のコミット対象とした。通常作業ツリーの別作業と配信は保持しているため、コミット後もそれらのソース・生成物の差分は残る。通常サーバーはこのrepoを指す独立プロセスを再利用する。
