# レベル13 開発・評価記録

役割: Lv13（仮称「真理カオスロジカルエンペラービースト」）の採用版と、その根拠になった開発比較の記録。ゲーム上の仕様の正本は [01-rulebook.md](../01-rulebook.md) §14.11、探索設定の正本は `game/ai/cpu-lv13-search.ts` の `LV13_SEARCH_CONFIG`。対局ログなどの実験データは `data/cpu-lv13/v2/`（Git管理外）にある。試した案を効果の大きさで並べた早見表は [試した案と効果の一覧](cpu-lv13-tried-ideas.md)。

## 採用版（2026-10-06。2026-10-07に第2段階を追加）

- 版 `lv13-card-use-margin`。探索・局面評価はLv12（`lv12-a04-additional-complete-root`）と同じ。
- 違いは1点だけ: カードを使う候補は、カードを使わない最善の候補より比較値（-1〜1）で `cardUseMargin = 0.1` 以上上回る場合だけ選ぶ。
- 予算は4,096遷移・4,700ms。1手の思考時間を5秒以内にするというユーザー指定に合わせた。
- ユーザーの判断で、正式な30局評価（勝率70%）は行わず、開発比較の最良案として組み込んだ。正式30局での達成は未確認。

## 比較の条件

- 相手: 作業開始時のLv12（コミット `949616fe5` のビルドを固定コピー）。
- 両者ともLv12のゲーム条件（同じデッキ・初期布石99・獲得2倍・解禁6手番）、持ち石ルールあり（既定）。
- 開発比較は時計を使わず遷移数だけで止める決定的な条件（両者2,048遷移）で、他のアプリによるPCの負荷の影響を除いた。同じ16個のseedで先後を入れ替える最大32局。
- ユーザー指定で、終了した最初の5局のうち3敗した候補は打ち切った。

## 分かったこと

- このゲームは序盤のカード運の影響が大きい。十分に試したseedの約3割は、どちらが打っても同じ色が勝った。同じ方針で計算量を2倍にしても56%程度にとどまる。
- Lv12が負けた対局の743局面のうち220局面を、約18倍の計算量で再解析した。手が食い違ったのは110局面で、その約75%が25手番未満だった。Lv12がカードを使った73局面では、55%で再解析と食い違った。宝箱を通常配置とほぼ同点で使うなど、価値の薄いカード使用が目立った。
- 4,096遷移を超える探索結果は、`game/ai/cpu-lv10-advisor-contract.ts` の受け渡し検査で無効になる。Lv13の予算は4,096遷移以内に保つ。

## 第2段階: 固有デッキ前提の改良（2026-10-07）

目的はユーザーの指示により「人間のプレイヤーと戦ったときの強さ」。人間とは直接対戦させられないため、CPU同士の自己対局で、特定の相手に合わせ込まない「打ち方の質」の改良だけを採用する方針にした。相手の手札読みの強化はユーザーの判断で対象外。

- 条件: Lv12・Lv13ともユーザーが組んだ固有デッキ（Lv12は112枚・43種類で特殊石が約75%、Lv13は117枚・67種類）。主な物差しは「改良版Lv13 対 採用済みLv13」（どちらもLv13のデッキと開始条件、時計なし2,048遷移、先後交換）。確認用に対Lv12も見る。
- 深い再解析: Lv13同士の自己対局24局から180局面を、計算量約18倍・仮想世界3組の読みで再判断した。損の内訳は通常配置の選び方が最大で、手札破壊がらみ（破壊より配置が良かった10件、別のカードを使うべきだった11件、破壊するカードの選択違い9件）が全体の約22%。序盤の損は平均以下、カードの選び間違いは特定のカードに偏らなかった。
- 採用: `destroyHandMargin = 0.08`（手札を破壊する手は、破壊しない最善手より0.08以上上回る場合だけ選ぶ）。版 `lv13-card-and-destroy-margin`。

| 候補 | 内容 | 対 採用済みLv13 |
| --- | --- | --- |
| X1 | カード使用の余裕幅0.05 | 2勝3敗で打ち切り |
| X2 | 手札破壊の余裕幅0.08（採用） | 19勝11敗2分、別seed 17勝15敗、さらに別seed 16勝16敗。合計96局52勝42敗2分（約55%） |
| X3 | 手札破壊の余裕幅0.15 | 0勝4敗1分で打ち切り |
| X4 | カード使用の余裕幅0.15 | 20局で8勝10敗2分、中止 |
| X5 | 手札破壊の余裕幅0.05 | 1勝4敗で打ち切り |

- 対Lv12（各自の固有デッキ、32局）: 採用前・採用後ともに21勝11敗（約66%）で差はなかった。X2の効果は小さく、統計的に確定した改善ではない。悪化の兆候がなく、手札破壊の回数が160回→98回に減ったことを深い再解析の指摘と合わせて採用した。

## 第3段階: 読みの高速化と遷移上限の引き上げ（2026-10-07）

- 目的は「同じ5秒でより深く・正しく読む」。盤面ビューの不変局面マーク、評価の共有ビュー化、反転列走査の簡素化、外周列挙の一括解決で、判断を一切変えずに1遷移あたり1.02ms→0.74ms（約27%高速化、固定計算量26局面で判断・評価値が完全一致）。
- 物差しを対局の勝敗から「後悔値」に変えた: Lv13自己対局の180局面を計算量約18倍・仮想世界3組で読んだ正解（`sp1-an-*.ndjson`）に対し、各設定の選んだ手の評価差の平均。32局の勝敗（誤差±9%）より桁違いに精度が高い。
- 後悔値（小さいほど良い。計算量は遷移数）: 2048=0.0334、3072=0.0292、4096=0.0258、6144=0.0244。探索の幅を広げる設定（深い候補5・応手3・追加候補2）は2048で0.0377、6144で0.0343と悪化。角の手に+0.05／空き角の隣に-0.08の補正は0.0332（差なし）、+0.1／-0.15は0.0347（悪化）。角・辺の評価重み2.3倍は0.0333（差なし。ただし同じ評価を使う正解との比較なので、評価変更の判定には使えない）。
- 採用: `maxTransitions` 4096→6144（時計4,700msは据え置き。高速化で4096では時間を使い切れていなかった）。版 `lv13-deeper-6144`。受け渡し検査の遷移上限は `LV10_ADVISOR_MAX_TRANSITIONS = 8192` に一般化。実時間では平均2,919遷移・3.4秒（24局面）で、上限に当たる局面だけ深くなる。
- 記録しておく失敗: Lv13のコードをLv12から作り直した際に、実験用の設定上書き（`tuning`・`valueWeights`）が消えていた。そのため同日の設定比較（幅広探索W1、上限W2、角補正C1、角辺重みG3、学び直し評価D1）は全て同一設定同士の対戦になっており無効。上書きを復元したうえで後悔値で測り直した。640局面の「正解評価」付け（蒸留用）も同じ理由で無効。評価の学び直しは、正解側も同じ評価関数を使う以上の伸びしろが小さい（相関0.74→0.77）と判断し、保留。
- 対局での確認（6144版 対 4096版、Lv13デッキ同士32局）: 16勝16敗。対Lv12（各自の固有デッキ、V0と同じ32条件）: 17勝15敗（4096版は21勝11敗）。いずれも32局の誤差の範囲で、後悔値の改善（約5%）は対局では検出できていない。上限引き上げは害がなく深い読みに近づくため採用するが、強さの上積みとしては小さい。
- 評価重みの対局検証（計算量512遷移の高速対局、Lv13デッキ同士、各128局）: 角・辺・危険マスをまとめた geometry の重みを2.3倍にすると66勝60敗2分（52%）、1.6倍で57勝70敗1分（45%）。単調でなく誤差の範囲で、重みの拡大だけでは改善しない。
- 角・危険マスの実態（自己対局56局・通常配置1,603手）: 角に置ける274回のうち角を取ったのは130回（47%）、空き角の隣に置いたのは158回（うち136回は他の手あり）。深い読みでも角候補13局面中8回しか角を選ばず、危険マスは31局面中4回（Lv13は7回）。このゲームでは角の価値が通常のリバーシより低く、強制ルール化はしない。

## 第4段階: 安定石の評価項目（2026-10-07）

- 動機: 重みの拡大・読みの深さでは伸びず、残る伸びしろは「何を良い局面とみなすか」。人間の観察（中盤までは角と連続した辺が大事で、連続した辺を覆せるカードは限られている）に沿って、Lv12 にはない特徴量を加えた。
- 実装: `countLv13StableStones`（`game/ai/cpu-lv13-evaluation.ts`）。角と、そこから途切れず続く辺の石、さらに縦・横・斜めの4方向すべてが「盤外・穴」「同じ色の安定石」「空きのない列」のいずれかで守られている石を固定点まで広げて数える（通常の配置では反転できない石の保守的な見積もり。穴・盤外は壁、盤面拡張は考慮しない）。特徴量 `stable`（黒−白を自分視点に）と `stableEnd`（終盤度を掛けたもの）を Lv12 の特徴量の後ろに追加。検索の実時間コストは約7%増（2048遷移×26局面の計測）。
- 係数の決め方: Lv13 自己対局182局面の深い読み（遷移12,288×仮想世界3組、`sp1-an-*.ndjson`）の評価に対し、他の係数を固定して残差に当てはめた（`harness/stablefit.js` / `stablefit.py`）。当てはめ値 1.18 / −0.44（中盤は安定石1個≒1.2石、終盤は約0.7石）。交差検証の誤差 28.55→27.97、相関 0.880→0.883 と小さく改善。中盤（40手未満）だけでは安定石がほとんど無く係数は定まらない。
- 対局検証（計算量512遷移の高速対局、Lv13デッキ同士、新しい種で各128局）: 当てはめ値 1.18/−0.44 は 68勝59敗1分（53.5%）、2倍強めの 2.5/−1.5 は 66勝62敗（51.6%）。合計256局で52.5%（誤差±3%）。害は無いが、強さの上積みとして検出できる大きさではない。
- 採用: 当てはめ値 1.18/−0.44 を本番の係数に入れ、版を `lv13-stable-6144` とした。読みの深さ・幅・ためらいの調整は出し切っており、評価項目の追加は今後の改善の土台として残す。学習ループ（自己対局→学び直し→採用試験）はユーザー判断で不採用。

## 第5段階: 外部調査の提案1「使わずに置く基準手を残す」の検証（2026-10-07、不採用）

- 出典: [Lv13 CPU を人間相手に強くするための調査・提案](cpu-lv13-human-strength-research.md) の提案1。根6枠・深読み3枠からカードを使わない手が全て押し出されると、カード使用のためらい（`cardUseMargin`）が掛からない。実例（自己対局 g005 白15手番、通常配置9手）で、修正前は深読み3候補が全てカードだったことを確認した。
- 実装した案: 根と深読みのそれぞれで、カードを使わず手札も捨てない最善の手番を1枠予約する（候補総数は増やさない）。案Aはさらにためらいを手番全体で判定（「捨ててから使う」手に両方のためらい）、案Bは予約だけ。
- 検証条件: 検証環境に「相手デッキを伏せる」条件（各探索に自分のデッキだけを渡す。人間が自作デッキで対戦する場面に相当）を追加。512遷移の高速対局、Lv13デッキ同士、各128局。
- 結果: 案A 39勝88敗1分（31%）、案B 47勝79敗2分（37%）。いずれも誤差（±4%）を大きく超えて弱い。案Aは手札を捨てる手が7.2%→0.8%に激減し、満杯の手札を回せなくなった。カード使用率は両案とも約26%→22%。
- 解釈: 候補が全てカードになる局面は、浅い比較の時点でカードが明確に良かった局面。そこへ通常配置を割り込ませると深読み枠が1つ減り、全カードにためらいが掛かって正しいカード使用を逃す。「比較相手がいないときはためらわない」現行の作りが正しい。回帰テスト `test/cpu.lv13-holding-baseline.test.ts` でこの挙動を固定した。
- 前提の確認（相手デッキの受け渡し）: 本番の `getPublicRecipes` は、黒・白の選択欄が固有デッキを持つCPU（Lv6以上）の場合だけそのデッキを渡す。仕様（01-rulebook.md「CPU対戦でカスタムデッキを使う場合」）上その席は実際にそのデッキを使うため、未公開情報の漏洩ではない。人間が自作デッキで遊ぶ通常の場面（黒がLv1〜5）では相手デッキは渡らない。変更なし。

## 第6段階: 意味のない・利敵になるカード使用の洗い出し（2026-10-08）

- 依頼: Lv13のカードの使い方で、明らかに意味がない、または相手を利する使い方を見つけて抑える。
- 材料: 採用版（`lv13-stable-6144`）同士の自己対局48局（相手デッキを伏せる・2,048遷移、`runs/SP2-selfplay-stable-hidden`）と、第5段階の高速対局の記録。カード使用は計約2,400回。
- 調べ方と結果（道具は `data/cpu-lv13/v2/harness/` の `cf*.js`・`imm*.js`・`noeffect.js`・`turnstats.js`・`stab*.js`・`budget*.js`・`curse.js`）:
  - 最後まで打ち切る比較（同じ局面から「カードを使う」と「使わない最善手」を同じ乱数で256遷移の自己対局で終局まで、160局面×2回）: 石差の差 −1.1±1.5、勝率差 0.00。平均するとカード使用は得でも損でもない。1局面ごとのばらつきが大きく、カード別の損得は読めない。
  - 相手の応手1手までの比較（カードを使った手番と、同じマスに普通に置くだけの手番、約1,900場面）: カード使用は応手後の石差で平均+2.2石。応手後に3石以上損した使用は7%。相手に新しく角を渡したのはテレポート35回中8回、強風の意志42回中5回で、全体平均（4%）より多い。強風の意志は応手後の石差が全カードで唯一マイナス（−0.4）。
  - 効果ゼロの使用（手番の終わりの局面がカード無しと全く同じ）: 約1,900回中8回（そのまま置けるマスへの自由の意志3回、連鎖が起きない連鎖カード5回。後者は後継カードが手札に来るので無駄ではない）。
  - 読みの量による判断の変化（320局面を2,048と16,384遷移で読み直し）: 2,048でカードを使った160局面のうち26局面（16%）が16,384では使わない手に変わり、逆は160局面中7局面（4%）。読みが浅いほどカードを使いすぎる。カードの効果乱数だけを変えて読み直すと、同じカードを選び直すのは63%（通常配置は90%）。
  - 原因の実例（自由の意志、SP2 g038 黒11手目）: 「自由の意志→(4,1)」と「(4,1)に置く」は盤面が全く同じなのに、2,048遷移の深い読みでは前者が0.12高く、仮想世界の1つでは23点差がついた。6,144遷移では正しく後者が上になる。読み不足のときの評価の揺れが、ためらい幅0.1を超えることがある。
- 試した抑制策:
  - F1: 読みの中の「将来の自分の手番」ではカードを使わせない（持っているカードは評価の手札点で数える）。122局で56勝63敗3分（47%）、さらに互いにパスを続けて終局しない対局が6局出た。不採用。

## 第16段階: 人間の対局条件の負けを無くす試み（2026-10-19、すべて不採用）

- 依頼: 人間の対局条件で勝率100%にする。
- 負けの調べ方: `AU3-fix4`（122勝5敗1分）の負け5局と引き分け1局を、白の各手番から読み直して評価の推移を見た（`valtrace3.js`、`runs/VT3-loss/`）。
- 分かったこと:
  - 6局とも、48手目の時点で白の持ち石が黒より2個以上少なかった。持ち石が同じだった100局は全勝だった。差は白の連続配置カード（2個置き・3個置き・4個置き）の使用で生まれる。
  - 持ち石の差を見積もる特徴量（`stonePlacementLead`）は「空きマスが先に埋まる」前提で、両者の持ち石が空きの半分以上ある間は0になる。実際の対局では、破壊などで空きが増え、終局時に平均6〜9マス空いている。片方の持ち石が尽きた後の1手番は、石差で約6〜7石に当たった。
  - 4局では、終盤に白の評価が0.8〜1.0（勝ち確定に近い）まで上がった後、黒の手札の逆転カード（交換の意志、究極反転龍、破壊、浮力など）で逆転された。
- 試した案（すべて不採用）:
  - 持ち石の見積もりで、空きマスに8を足す（空きが残る前提にする）。白の連続配置カードの使用は65局で31回から19回に、48手目に持ち石が2個以上少ない局は9局から5局に減った。それでも負けは4局のまま、同じシードの対で石差−2.5（標準誤差1.7）、勝ち点±0（同0.040）で、65局で止めた（`AU4-slack8`）。持ち石の差は負けの原因というより、展開の結果と判断した。
  - 残り12配置以下で仮想世界を3から5に増やす（`late5`）。終盤の対比較81組で勝ち点−0.056（標準誤差0.033）、石差−1.5（同1.6）。
  - 残り12配置以下で終局まで読む手番を2から4に増やす（`deep4`）。64組で勝ち点−0.078（同0.039）、石差−1.8（同1.4）。読む量を増やすと弱くなる傾向は第11段階と同じ。
  - 読みの中の終局の勝ちを、石差で強く重み付けする（1石差0.56、8石差0.88、20石差0.99。`term8`）。100組で勝敗はすべて同じ、石差+0.15（同0.13）。
- 終盤の対比較（`endbench.js`）: 128局のうち、白の手番で残り12配置以下に達した71局について、その局面から乱数を3通り変えて終局まで打つ。基準（`lv13-no-corner-gift`）は213回で199勝13敗1分。この時点で20石以上リードしていても、持ち石が黒より3〜5個少ない局（g013・g050・g024）は、3回中2〜3回負けた。
- 結論: 残る負けは、黒が終盤に使う強いカードと、それを受ける白の持ち石の不足が重なって起きる。どちらも、読む量・評価・終局の重みの変更では減らせなかった。カードの効果とデッキの偏りで決まる部分があり、今の方式で勝率100%を保証する手段は見つかっていない。
- 実験データ: `data/cpu-lv13/v4/runs/VT3-loss/`・`MD1-slack8/`・`AU4-slack8/`（65局で停止）・`EB1-late/`。実験用ビルドは `C:\Users\quarr\cr-lv13x\fix5`（持ち石の余裕、環境変数 `LV13_SUPPLY_SLACK`）、`fix6`（終盤の設定 `LV13_LATE_WORLDS`・`LV13_LATE_TUNING`、終局の重み `LV13_TERM_SCALE`）。
