# Godot移植準備 実行計画

役割: 今回の準備作業の実行・引き継ぎ記録。対象は既存カードリバーシの移植元、公開契約、比較基盤と証拠。ルールの一次情報は `01-rulebook.md`、詳細は `正本/`、内部契約は `architecture-contracts.md`。Godotゲーム本体、新カード、バランス変更、追加学習、外部公開は対象外。

## 採用方針と既存変更

- 開始HEAD: `bfd7ee626` (Add Reincarnation Will card with synchronized roulette)。作業開始時の状態と既存tracked差分は `output/godot-port-preparation/initial-status.txt`、`preexisting-tracked.patch` に保存。
- 未コミットのCPU Lv13・性能改善・素材制作は今回の正式採用に含めない。移植元は開始HEADと今回検証した変更を明示して再構成する。実行中のdirty作業ツリーと採用版は別物として記録する。
- 既存変更は巻き戻さない。生成物を手編集しない。共有ファイルのステージは今回分だけを分離する。元の歴史fixtureを保持する。

| フェーズ | 所有範囲 / 担当 | 完了条件 |

## 検証束

最初に転生の意志とbattle互換テスト。担当ごとの対象テスト、JSON比較と不正入力検査、CPU固定量/実時間測定、素材参照検査、実ブラウザ演出とライフサイクル確認を行う。最終ソースで型検査・生成・同期検査を実行し、必要な関連テストを統合する。ゲーム変更時は `npm run build:vite` と8000の継続稼働・所有者確認を行う。リモートCI未実行とGodot未実装は明示する。
