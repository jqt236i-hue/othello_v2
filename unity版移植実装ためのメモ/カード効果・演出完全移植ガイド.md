# Unity版カード効果・演出完全移植ガイド

作成日: 2026-06-02

この文書は、ブラウザ版カードリバーシのカード効果、カード演出、SE/BGM、対象選択、特殊石表示を Unity 版 `C:\Users\quarr\Documents\CARD-REVERSI` へ Codex だけで移植するための実装メモです。

目的は「カードが使える」ではなく、ブラウザ版の正本仕様と実装挙動を Unity で再現し、DebugSandbox とテストでカードごとの退行を検出できる状態にすることです。

## 3. 移植完了の定義

カード効果の「完全移植」は、各カードで次を満たすことです。

- `catalog.json` の有効カードが Unity 側に全て存在する。
- コスト、表示名、説明文、使用可否がブラウザ版と一致する。
- カード使用時のコスト消費、手札移動、捨て札、ドロー、手札上限が一致する。
- 使用不可条件が一致する。
- 即時効果、配置予約効果、対象選択効果、ターン開始効果、持続ターン減算、期限切れ処理が一致する。
- PRNG を使う効果は `SeededPrng` だけを使い、同じ局面で再現可能にする。
- 特殊石、石状態、盤面マーカー、爆弾、穴、凍結、封鎖、数字マス消費が保存/復元可能な状態として残る。
- 対象選択 UI は、Domain の合法対象だけを選べる。
- `selectTarget` 完了で効果確定するカードは、演出完了まで入力を再開しない。
- 演出は `01-rulebook.md` の `12. UI/演出仕様` に従う。
- SE/BGM は `01-rulebook.md` の `12.15 サウンド既定値` とブラウザ版 `sound-engine.ts` の soundKey / 音量倍率に従う。
- DebugSandbox で全カードを任意局面に対して検証できる。
- EditMode / PlayMode テストでカード効果と主要演出イベントを検証できる。

### Phase 1: 共通基盤

カード個別実装の前に、共通基盤を整えます。

- `CardType` は文字列でもよいが、typo 検出用の定数またはテストを置く。
- `CardState` に必要な pending 系を揃える。
  - `PendingEffects`: 次の配置に効果を乗せる。
  - `PendingTargets`: 盤面対象選択。
  - `PendingHandTargets`: 相手手札対象選択。
  - `PendingCardOffers`: 天の恵みなどの候補選択。
- `StoneMarker` で特殊石本体、石状態、盤面マーカー、爆弾、穴、凍結を表現する。
- ただし 2026-06-02 時点の Unity 現行 `StoneMarkerKind` は `Protected` / `PermaProtected` / `Blocked` / `Frozen` / `Special` の5種だけで、ブラウザ正本の `特殊石`、`石状態`、`爆弾`、`隠し罠`、`盤面マーカー`、`配置時効果` を型として分離していない。完全移植では、既存5種で足りるかをカードごとに検証し、不足する場合は marker metadata または型を拡張する。
- 現行 Unity では穴/封鎖は主に `StoneMarkerKind.Blocked`、凍結は `StoneMarkerKind.Frozen`、多くの特殊石/爆弾/罠/状態は `StoneMarkerKind.Special` + `CardType` で表現される。`CardType` だけで判定が分散しないよう、共通 helper を作る。
- `CardStateOperations` に共通操作を集約する。
  - 反転可否
  - 破壊可否
  - 回避
  - 保護
  - 特殊石通常石化
  - 対象存在チェック
  - 盤面マーカー追加/削除
  - 手札破壊/ドロー/捨て札
  - 布石 ledger
- Unity 現行コードには `TurnTrace.PresentationEvents` / `TurnTraceEvent` がある。まずこの既存構造を確認し、必要なら `PresentationEvent` 相当へ拡張する。新しいイベント型を足す場合も、Domain ではなく Application 以降に置く。
- 現行 Unity の `PendingPlacementKind` は `None` / `FreePlacement` / `ProtectedNextStone` / `PermaProtectedNextStone` / `SpecialNextStone` / `FreeSpecialNextStone` / `CrossBomb` / `XBomb`。`REVERSE_WILL`、`SUPPORT_TROOPS_WILL`、盤面形状の複数選択などは既存 pending enum だけで自然に表せるとは限らないため、既存型への無理な詰め込みを移植完了扱いしない。

## 5. カード効果ファミリー別の実装指針

### 即時リソース系

対象:

- 宝箱
- 補給の意志
- リボ払いの意志
- 角の代償
- 吸収の意志
- 出稼ぎの意志の収入
- 盤理の観測者の成功報酬
- ラウンドボーナス

実装:

- 布石変更は `CardStateOperations.AddCharge` / `SetCharge` に集約する。
- 変化理由を `ChargeDeltaEvent` に残す。
- Presentation は HUD 側 `+N` / `-N` を表示する。
- 反転絡みの布石獲得と数字マス獲得は盤面内にも `+N` を出す。

### 配置予約系

対象:

- 自由の意志
- 最後の切り札
- 弱い意志
- 強い意志
- 幽霊の意志
- 避ける意志
- 復活の意志
- 狙撃の意志
- 各種特殊石化カード
- 爆弾/十字爆弾/クロス爆弾
- 金/銀/虹/演算/理論
- 二連投石/連鎖系

実装:

- `PendingCardEffect` に `SourceCardId`、`CardType`、`PlacementKind`、残配置回数、追加連鎖数、特殊石 metadata を持たせる。
- 現行 Unity の `PendingCardEffect` は `SourceCardId`、`CardType`、`PlacementKind`、`OwnerTurnsRemaining`、`FlipEvadesRemaining`、`DestroyEvadesRemaining`、`PlacementsRemaining`、`WorkStage` を持つ。複数候補、複数対象、経路、effect block、音声キー、演出 phase は持っていない。
- 置いた瞬間に `ApplyPendingPlacementEffect` で確定する。
- 特殊石は配置直後から最終見た目を出す。遅延差し替えは禁止。
- 配置予約はパス時に破棄する。ただしカード使用とコスト消費は戻さない。

### 盤面対象選択系

対象:

- 破壊の意志
- 交換の意志
- 入替の意志
- 強風/浮力/重力/超浮力/超重力/超引力
- 誘惑/捕獲
- 延命/腐食/守護
- 封鎖/凍結/隕石
- 盤面拡張/縮小
- 複製/テレポート/マステレポート

実装:

- 対象候補は `CardTargeting.GetTargets` が唯一の正本になる。
- ただし `PendingHandTargets`（断罪の意志）と `PendingCardOffers`（天の恵み）は盤面座標ではないため、`CardTargeting.GetTargets` の対象外。盤面対象、手札対象、候補カード選択を混ぜない。
- Presentation は候補を表示するだけで、独自に対象可否を判定しない。
- 選択確定は `CardTargeting.ResolveTarget` へ集約する。
- `EndsTurnAfterResolve` のカードは、対象選択完了で配置せず手番終了する。
- キャンセル可否は `CardTargeting.CanCancelPendingSelection` に集約する。
- 現行 `TargetEffectKind` は `None`、`DestroyOneStone`、`SwapWithEnemy`、`GuardStone`、`BlockadeCell`、`FreezeCell`、`PositionSwap`、`TeleportStone`、`MarkOwnStoneSpecial`、`MarkEmptyCellSpecial`、`ExtendOwnSpecialDuration`、`CorrodeSpecialDuration`、`MeteorCell`、`CloneOwnStone`、`DirectionalMove`、`TemptSpecial`、`CaptureSpecial`、`CellTeleport`、`SuperAttraction`、`BlockCell`。`REVERSE_WILL` や `SUPPORT_TROOPS_WILL` のように未登録の type を既存 kind に便宜的に割り当てる場合は、ブラウザ仕様とテストで妥当性を証明する。

### 保護・回避・無効化

対象:

- 弱い意志
- 強い意志
- 最強の意志
- 守る意志
- 守護神
- 幽霊の意志
- 避ける意志
- 復活の意志
- 増殖の意志
- 生きる意志
- 救済神

実装:

- 保護と回避は対象効果側に分散させず、共通の `CanFlip` / `CanDestroy` / `TryConsumeEvasion` に寄せる。
- `ABSOLUTE_PROTECTED` は `TABOO_REVERSE_WILL` でも貫通できない。
- Unity 現行 enum には `ABSOLUTE_PROTECTED` 専用の `StoneMarkerKind` はない。`PERMA_PROTECT_NEXT_STONE` から所有者ターン開始10回で昇格する「最強の意志」を移植する場合は、永続保護とは別ティアとして表現し、隕石/盤面縮小/セル破壊への耐性差まで検証する。
- 幽体は反転列成立を妨げないが、自身は反転/破壊されない。
- 復活/残像/増殖/救済は「破壊対象として狙われた演出」は出し、実結果は共通処理で無効化する。

## 6. PresentationEvent / TurnTrace 設計

ブラウザ版の `events[]` は UI が順番どおり再生するための正本です。Unity 側では、現行の `Application/TurnTracing.cs` に `TurnTrace.PresentationEvents` と `TurnTraceEvent` があるため、まずこれを移植先のイベント列として扱います。

現行 `TurnTraceEvent` が持つ主なフィールド:

```csharp
public sealed class TurnTraceEvent
{
    public string Type { get; }
    public Player Player { get; set; }
    public string CardId { get; set; }
    public string Reason { get; set; }
    public CellPosition? Position { get; set; }
    public int? Value { get; set; }
    public bool? Flag { get; set; }
}
```

ブラウザ版の parity を厳密に取るには、必要に応じて `Phase`、`CauseCardType`、複数 targets、`SoundKey` などを追加する。追加する場合の拡張例:

```csharp
public sealed class PresentationEvent
{
    public string Type;
    public int Phase;
    public string CauseCardType;
    public string Reason;
    public IReadOnlyList<PresentationTarget> Targets;
}

public sealed class PresentationTarget
{
    public int Row;
    public int Col;
    public Player Owner;
    public string StoneType;
    public string SoundKey;
    public string Text;
}
```

主な `Type` 候補:

- `card_use`
- `hand_remove`
- `draw`
- `place`
- `flip`
- `destroy`
- `spawn`
- `move`
- `crossfade`
- `status_change`
- `charge_delta`
- `sound_effect`
- `observer_bubble`
- `board_expand`
- `board_shrink`
- `cell_block`
- `cell_freeze`
- `cell_hole`

ルール:

- Application はイベント列を発行するが、再生しない。
- Presentation はイベント列を順番に再生する。
- 再生中の盤面表示は Presentation の単一経路で更新する。
- 不明イベントはアニメ無しで最終状態へ同期し、再生を止めない。
- `selectTarget` 完了で確定する効果は、イベント再生が完了するまで入力ロックする。
- `TurnTraceEvent` の現行フィールドだけで表現できない演出を、Presentation 側の推測で補完しない。必要な情報は Application 側イベントへ明示的に載せる。

## 7. 演出移植の基準

`01-rulebook.md` の `12. UI/演出仕様` を正本にします。

### 基本テンポ

- 通常反転フリップ: 約 `0.46秒`
- `FLIP_MS = 600`
- `PHASE_GAP_MS = 200`
- `TURN_TRANSITION_GAP_MS = 200`
- `FADE_IN_MS = 300`
- `FADE_OUT_MS = 500`
- `OVERLAY_CROSSFADE_MS = 600`
- `MOVE_MS = 400`
- `OBSERVER_BUBBLE_MS = 3000`
- `OBSERVER_BUBBLE_FADE_MS = 700`
- 手置き演出: 約 `0.44秒`
- ドロー手演出: 約 `0.56秒`

Unity 側では、秒単位の coroutine / tween へ換算して実装します。

### 色・ハイライト

- カード効果由来の破壊/爆発: 対象セルを半透明赤で表示。
- 破壊が幽体/増殖/復活などで無効化された場合も、狙われた対象セルは赤で表示。
- カード効果由来の反転/生成/配置/移動/状態変化: 対象セルを半透明紫で表示。
- 移動系: 移動先を紫表示。
- 入替の意志: 入替元と入替先を両方紫表示。
- 破壊回避の移動: 元マスを赤表示。
- 封鎖/凍結: 専用の赤バツ/氷表示を使い、追加ハイライトは出さない。

### 特殊演出

- 連鎖系: 一次反転、連鎖1、連鎖2の順に再生。同時再生しない。
- 復活の意志: 敵色への一時フリップを省略し、クロスフェード優先。
- 時限爆弾: 爆弾本体、周囲爆破の順。
- 移動系: 強風、入替、多動系は移動距離に依存しない固定時間。
- 入替の意志: 通常移動の80%時間。
- 罠の意志: 発動/不発まで通常石見た目。設置者にも罠見た目を見せない。
- 盤面拡張: 新規セルを短いフェードインで表示。
- 狙撃の意志: 狙撃石から対象へ通常石画像25%サイズの小球を飛ばし、到達後破壊。
- 破壊龍: 炎ブレスを約0.28から0.52秒表示してから破壊。
- 究極破壊神: 対象へ雷演出を表示してから破壊。
- 落雷: 高品質の落雷演出を表示してから破壊。
- ロボット掃除機: 吸い込み破壊だけ吸い込み演出。
- 悪食: 捕食破壊と進入移動を同一フェーズで再生。
- 隕石/盤面縮小: 穴化または外枠押し込みを永続表示。
- 凍結: `ICE.png` 相当を半透明で重ね、石も凍った見た目を維持。
- 盤理の観測者/出稼ぎの意志/特殊石吹き出し: 石の近くに約3秒表示し、フェードアウト。クリック操作を妨げない。

## 8. SE/BGM 移植

基本:

## 13. 失敗しやすい点

- `CardEffectRegistry` に登録されているだけで「移植済み」と判断する。
- 盤面結果を Presentation 側で補正する。
- 対象候補を UI 側で独自判定する。
- DebugSandbox のためにカード効果へ例外分岐を入れる。
- PRNG を `UnityEngine.Random` や `System.Random` で直接呼ぶ。
- 期限切れ通常石化を破壊として扱う。
- 幽体を保護石と同じ扱いにして合法手判定を壊す。
- 完全保護と絶対保護を同一扱いにする。
- 盤面縮小/隕石/穴化を単なる石破壊として扱う。
- 罠石を設置直後に見た目で公開する。
- `selectTarget` 解決後、演出が終わる前に入力を戻す。
- SE/BGM を Domain や Application から直接鳴らす。
- ブラウザ版 `worker-public/` や生成 catalog を正本として編集する。
- Unity版の対象外機能まで「完全移植」に含めて、network battle、gacha、deck creation、story、ML/ONNX/selfplay を同時に実装し始める。
- Unity側の保存/復元、DebugSandbox、editor tools、音量既定値を確認せず、Domain 実装だけで完了扱いにする。
