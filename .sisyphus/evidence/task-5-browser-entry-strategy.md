## Conservative Strategy

1. Browser-loaded `.js` files must be either a browser-classic-artifact or a browser-safe-adapter.
2. Do not point classic `<script>` tags at `dist/` output unless that exact `dist/` file has been proven browser-safe as a classic script.
3. Treat current `dist/` as CommonJS-risky by default because it may emit `module.exports`, `exports`, or `require`.
4. Preserve the current HTML load order unless an intentional migration explicitly documents and verifies the order change.
5. Keep existing script paths stable while migrating whenever possible; replace unsafe shim contents with browser-safe adapters instead of changing HTML first.
6. Do not introduce a bundler as part of this strategy.

## Category Definitions

- `browser-classic-artifact`: a root/public `.js` file intended to be loaded directly by a classic browser script tag, with no dependency on CommonJS globals. It may populate `window.*` or other browser globals intentionally.
- `browser-safe-adapter`: a root/public `.js` adapter at the browser-loaded path that is safe as a classic script and bridges TS-generated implementation into the existing browser global contract without exposing `module.exports` or calling `require` in the browser.
