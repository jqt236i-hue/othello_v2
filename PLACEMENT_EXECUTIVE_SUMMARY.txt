║  PLACEMENT DECISION ASYMMETRY: SELFPLAY vs PRODUCTION (Lv6 CPU)           ║
║  Executive Summary for Improvement                                         ║
╚════════════════════════════════════════════════════════════════════════════╝

PROBLEM
───────
Lookahead in SELFPLAY can override forced corner/edge intuition by exploring
the FULL legal move space and returning any move with highest tree value.
PRODUCTION always constrains lookahead to forced moves (corners/edges) via
hard filtering BEFORE lookahead. This creates misalignment in training.

ROOT CAUSE
──────────
src/engine/selfplay-runner.js, Line 2062-2064:

  const candidateMoves = (options && options.enableTacticalLookahead === false 
      && Array.isArray(forcedPlacement.moves) && forcedPlacement.moves.length > 0)
      ? forcedPlacement.moves
      : defaultCandidateMoves;  // ← ALLOWS ALL moves when lookahead enabled

When enableTacticalLookahead=true (normal case):
  ✗ candidateMoves = ALL legal moves
  ✗ chosenPlacementMoveByBrowserParity() receives ALL moves
  ✗ CpuPolicyCore.chooseMoveByLookahead(candidateMoves=ALL) explores full space
  ✗ Lookahead returns highest tree value, which may NOT be corner/edge
  ✗ maybeOverrideWithStrictPendingPlacement() has NO guardrail against non-forced

Compare to PRODUCTION (game/cpu-decision.js, Line 3137):

  const prioritizedCandidateMoves = filterMovesByLv6PlacementPriority(...)
  // Returns: corners (if exist) | edges (if exist) | all (no corners/edges)
  
  const looked = CpuPolicyCore.chooseMoveByLookahead(prioritizedCandidateMoves)
  // Lookahead ONLY sees constrained move space
  // Result guaranteed to be forced or unconstrained

SOLUTION
────────
Replace line 2062-2064 with hard-filter logic (OPTION A - RECOMMENDED):

  const candidateMoves = (Array.isArray(forcedPlacement.moves) 
      && forcedPlacement.moves.length > 0
      && !(options && options.disableCornerEdgeHardFilter === true))
      ? forcedPlacement.moves   // ← HARD FILTER: respect forced
      : defaultCandidateMoves;

Effect:
  ✓ Constrain candidateMoves to forced moves (corners/edges) if they exist
  ✓ Lookahead explores ONLY constrained set
  ✓ Aligns SELFPLAY training with PRODUCTION behavior
  ✓ Removes non-intuitive moves where lookahead escapes forced placement
  ✓ Maintains lookahead agency within forced set (pick best corner vs best edge)
  ✓ Benchmark-safe if corner/edge strategies are well-trained by movePlanContext
