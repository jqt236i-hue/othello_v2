# Unity 移植 Test Scenarios

この文書は、Unity 版を実装した後に手順で確認するシナリオ集です。網羅チェックは `parity-checklist.md`、実装順は `implementation-phases.md` を参照する。

## 1. リバーシモード

1. リバーシモードで新規対局を開始する。
2. 黒=人間、白=CPU になっていることを確認する。
3. 手札、山札、カード詳細、捨て札、布石 UI が表示されないことを確認する。
4. 数字マス、特殊石、カード由来ターン開始効果が発生しないことを確認する。
5. 合法手がある状態ではパスできないことを確認する。
6. 合法手が 0 の状態ではパスできることを確認する。
7. 通常リバーシとして終局し、勝敗が表示されることを確認する。

期待結果:

- カードリバーシ専用 UI とカード系ルールが完全に無効。
- CPU レベルは白設定に従う。

## 2. デフォルトデッキと手札

1. CPU 対戦またはローカル対戦で新規対局を開始する。
2. 有効カード ID から重複なし 30 種が選ばれることを確認する。
3. 黒白のデッキ内容 30 種が共通であることを確認する。
4. 黒白の山札順が別シャッフルであることを確認する。
5. 初期手札が黒白とも 0 枚であることを確認する。
6. 手札が 5 枚の状態で通常ドロー機会を発生させる。
7. 通常ドローが失敗し、そのドロー機会が消えることを確認する。

期待結果:

- `enabled:false` 6 件は通常山札に入らない。
- `TRIPLE_*`, `QUAD_*`, `INFINITE_*` 系は連続効果でのみ到達する。

## 3. 宝箱 RNG

1. 固定 seed で `TREASURE_BOX` を手札に入れる。
2. 宝箱を使用する。
3. 布石獲得が 1..3 の範囲になることを確認する。
4. 同じ seed / 同じ状態 / 同じ入力で同じ獲得値になることを確認する。
5. RNG が注入されていないテスト構成で使用し、成功扱いにならないことを確認する。

期待結果:

- deterministic RNG が正本。
- 宝箱では `card_use_button` を再生しない。

## 4. 対象選択カード

1. `DESTROY_ONE_STONE` を使用する。
2. 破壊対象候補が表示されることを確認する。
3. 対象を選択して破壊が解決されることを確認する。
4. `BLOCKADE_WILL` を使用し、キャンセル可能であることを確認する。
5. `TIME_BOMB` を使用し、キャンセル不可であることを確認する。
6. `BOARD_SHRINK_WILL` を使用し、3 対象を選ぶまで解決しないことを確認する。
7. `POSITION_SWAP_WILL` を使用し、2 対象を選ぶまで解決しないことを確認する。
8. `HEAVEN_BLESSING` と `CONDEMN_WILL` が hand / candidate overlay として解決されることを確認する。

期待結果:

- pending selection 33 種類の kind / turnOutcome / cancel / dispatch / target resolver が一致する。
- CPU も pending selection を経由する。

## 5. 救済神

1. `STONE_SALVATION_GOD` を使用し、次配置石を救済神化する。
2. 救済神が盤面にいる状態で石を破壊する。
3. 破壊された石が救済神の持ち主の通常石としてランダム空きマスに復活することを確認する。
4. 両プレイヤーの救済神がいる状態で石を破壊する。
5. 破壊された石の元所有者側の救済神が優先されることを確認する。
6. 救済神自身を破壊する。
7. 救済神自身が復活せず、その効果が終了することを確認する。
8. マステレポートの移動元穴化など、石破壊を伴わない穴化では救済神が発動しないことを確認する。

期待結果:

- 救済神は「自分の石だけを復活」ではない。
- rescue spawn は元 destroy と同じ effect block 文脈を保持する。

## 6. 凍結と封鎖

1. `FREEZE_WILL` でマスを凍結する。
2. 凍結中に、そのマスと石が反転・破壊されないことを確認する。
3. 凍結中は特殊石の持続ターンが減らないことを確認する。
4. 凍結 overlay に `ICE.png` 相当が表示され、終了時にフェードアウトすることを確認する。
5. `BLOCKADE_WILL` で空きマスを封鎖する。
6. 封鎖中は配置や移動で入れないことを確認する。
7. 封鎖は赤バツ表示を使い、追加の一時マスハイライトを出さないことを確認する。

期待結果:

- 凍結と封鎖は専用表示を使う。
- 盤面状態と表示が同じタイミングで収束する。

## 7. 盤面拡張と縮小

1. `BOARD_EXPANSION_WILL` を使用し、左右外側に1マス追加する。
2. `BOARD_EXPANSION_GOD` を使用し、角外側に3..6マス追加する。
3. `BOARD_SHRINK_WILL` を使用し、外周から3マス選んで同時に穴化する。
4. `BOARD_SHRINK_GOD` を使用し、選んだ辺1列を同時に穴化する。
5. 絶対保護石があるマスは穴化されないことを確認する。
6. 盤面縮小の穴化では外側フレームが押し込まれた見た目を残すことを確認する。

期待結果:

- ベース盤面 `4..10` と拡張セルを別枠で扱う。
- 盤面形状と合法手判定が一致する。

## 8. 専用破壊演出

1. `SNIPER_WILL` の狙撃破壊を発生させる。
2. 狙撃石から対象へ小球が飛んでから破壊されることを確認する。
3. `DESTROY_DRAGON_WILL` のブレス破壊を発生させる。
4. 発動元から対象へブレスが出てから破壊されることを確認する。
5. `LIGHTNING_WILL` と `ULTIMATE_DESTROY_GOD` の破壊を発生させる。
6. 対象マスへ雷演出が出てから破壊されることを確認する。
7. `ROBOT_VACUUM_WILL`, `GLUTTONOUS_WILL`, `WILL_HUNTER_KING` の専用 profile を確認する。

期待結果:

- `SPECIAL_DESTROY_TARGET_PROFILES` 相当を汎用 destroy に潰さない。

## 9. Spawn 系演出

1. `BREEDING_WILL` の生成を発生させる。
2. `EQUALITY_WILL` と `REINFORCEMENT_WILL` の生成を発生させる。
3. `SALVATION_WILL` と `STONE_SALVATION_GOD` の復活生成を発生させる。
4. `SEED_WILL` の芽生え生成を発生させる。
5. `CLONE_WILL` と `PROLIFERATION_WILL` の生成を発生させる。
6. 生成先が強調表示されることを確認する。

期待結果:

- `POSITIVE_SPAWN_LIKE_EFFECTS` 相当の見え方になる。
- 生成後に反転が起きるカードは、反転 event も順序通りに再生する。

## 10. 追加配置と連鎖

1. `DOUBLE_PLACE` を使用し、2連続配置できることを確認する。
2. `TRIPLE_PLACE`, `QUAD_PLACE`, `INFINITE_PLACE` が通常山札に出ないことを確認する。
3. 連続効果として到達した場合は定義通りに処理されることを確認する。
4. `DOUBLE_CHAIN_WILL` を使用し、反転後の追加反転が1列発生することを確認する。
5. `TRIPLE_CHAIN_WILL`, `QUAD_CHAIN_WILL`, `INFINITE_CHAIN_WILL` が通常山札に出ないことを確認する。
6. 追加配置中に通常のターン開始効果が再実行されないことを確認する。

期待結果:

- disabled 連続カードは通常候補ではなく、連続定義としてのみ扱う。

## 11. CPU 対戦とリザルト

1. CPU 対戦を固定 seed で開始する。
2. CPU が `GameCommand` を発行して着手することを確認する。
3. 標準 `8x8` 以外で安全な通常判断へ切り替わることを確認する。
4. 対局を終局させる。
5. リザルト表示順が `勝敗タイトル` → `石枚数` → `最終スコア` → `スコア補足` → `観測石獲得` → `スコア内訳` → `モンスター台詞` になることを確認する。
6. 引き分け/敗北時は `観測石 +100（基本100 / 追加0）` になることを確認する。
7. 勝利時は `100 + 追加ドロップ` になることを確認する。
8. 追加ドロップが `100..3000`、`10` 刻み、線形重み `weight(k) = 291 - k` に従うことを確認する。
9. ランキング送信や共有ランキング文言が出ないことを確認する。

期待結果:

- CPU 対戦は終局できる。
- 観測石はガチャ消費導線やランキングへ接続しない。
