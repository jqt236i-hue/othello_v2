# Unity 移植スコープ

この文書は、Unity/C# 版の初期移植で実装する範囲と、明示的に実装しない範囲を固定するためのメモです。

## 初期移植で実装する

- ローカル対戦
- CPU 対戦
- リバーシモード。黒=人間、白=CPU とし、カード・デッキ・手札・布石・数字マス・特殊石・カード由来のターン開始効果を無効にする
- 盤面サイズ設定。ベース盤面は縦横 `4..10`、既定は `8x8`
- 標準 `8x8`、偶数サイズ、`7x7`、その他奇数サイズの初期配置
- 数字マスの初期抽選、消費、カスタム盤面時の配分
- デフォルトデッキの対局開始時ランダム選出と黒白別シャッフル
- 既存カードの挙動
- 既存カードの演出
- 手札、山札、捨て札、布石
- 初期手札 0 枚、手札上限 5 枚、5 枚時の通常ドロー失敗
- 通常石、特殊石、爆弾、穴、封鎖、凍結、種などの盤面状態
- 盤面拡張、盤面縮小
- ターン開始効果、配置時効果、反転後効果、ターン終了効果
- 対象選択 UI
- カード詳細表示
- ルール説明表示
- チュートリアル相当のルール確認導線。ストーリー進行とは分離する
- ゲーム画面、ポーズ、設定、リザルト
- 演出速度、音量などのローカル設定
- CPU レベル別の基本挙動と、標準 `8x8` 以外での安全な通常判断への切り替え

## 初期移植で実装しない

- ランキング
- オンライン対戦
- ガチャ
- ストーリー
- デッキ作成機能

## デッキ作成なしで残すデッキ仕様

デッキ作成画面は作らないが、対戦用デッキそのものは必要である。

- 初期 Unity 移植では、デフォルトデッキのみを使う。
- デフォルトデッキは、有効カード ID から重複なしで 30 種をランダム選出した 30 枚。
- ローカル対戦 / CPU 対戦では、新規対局またはリセットごとにデフォルトデッキを再抽選する。
- 両者ともデフォルトデッキの場合、30 種の内容は黒白で共通にし、山札順は黒白それぞれ別にシャッフルする。
- カスタムデッキの UI、保存、deck code 入出力、ネット room deck は初期移植では作らない。

## リザルトと報酬

- リザルト画面は実装対象。
- CPU 対戦のリザルトでは、観測石獲得表示とローカル所持数更新を実装する。
- CPU 対戦の観測石は勝敗に関係なく基本 `100` を獲得し、勝利時だけ `100 + 追加ドロップ` とする。
- 追加ドロップは `100..3000` を `10` 刻みで選び、線形重み `weight(k) = 291 - k` を使う。
- ランキング送信、ランキング表示、自己ベスト保存は実装しない。
- ガチャを実装しないため、観測石を消費する導線は作らない。
- ネット対戦の観測石獲得は、オンライン対戦を実装する将来フェーズまで扱わない。

## 将来実装を見据えて残す設計方針

- ゲームロジックは Unity の `MonoBehaviour` や `GameObject` に依存させない。
- UI 操作は直接状態を書き換えず、コマンドとして GameCore に渡す。
- 乱数は seed 管理できる専用 RNG を使い、UnityEngine.Random をロジック層で直接使わない。
- 盤面状態、手札、カード状態、pending selection はシリアライズしやすい単純なデータで保持する。
- 表示は GameCore が返す presentation event を順番に再生する。

## 初期移植の完了条件

- JS 版と同じ初期カードプールでローカル対戦が最後まで遊べる。
- CPU 対戦が開始から決着まで進行できる。
- 全有効カードが使用条件、対象選択、効果、演出イベントのいずれかで扱われる。
- catalog 上のカード 88 件のうち、有効 82 件を通常候補として扱う。
- `enabled:false` のカードは通常の山札/手札に出ない。
- `enabled:false` の 6 件、`TRIPLE_CHAIN_WILL` / `QUAD_CHAIN_WILL` / `INFINITE_CHAIN_WILL` / `TRIPLE_PLACE` / `QUAD_PLACE` / `INFINITE_PLACE` は連続効果の定義としては扱える。
- 盤面拡張/縮小、特殊石、破壊、復活、生成、移動が同じ順序で処理される。
- 初期対象外機能が画面導線やデータ設計に混入していない。
