## 判定区分

| 判定 | 意味 |
| --- | --- |
| 正本へ寄せる | 現挙動がバグ、漏れ、ネット対戦差分、演出/音欠落であり、実装側を直す。 |
| 正本を更新 | 現挙動の方が遊びやすい、理解しやすい、または既に正式仕様として採用したい。先に正本を更新する。 |
| 一致 | 正本と現挙動が一致している。 |
| 要判断 | 仕様としてどちらが正しいか決める必要がある。 |
| 未確認 | まだ現挙動を確認していない。 |

## 信頼度区分

| 信頼度 | 意味 |
| --- | --- |
| A: テスト済み | 自動テストで対象の主張を直接または十分近い形で確認している。 |
| B: 複数サーフェス一致 | 実装、生成物、ヘルプ文面、正本/ルールブックなど複数の現行サーフェスの読み取りが一致しているが、専用テストまではない。 |
| C: 手動確認 | CPU戦、ローカル対戦、ネット対戦、録画、スクリーンショットなどで手動確認した。 |
| D: 未確認 | 根拠が足りない。実装へ寄せる判断に使わない。 |
| X: 差分あり | 正本と現挙動に差分がある。正本へ寄せる、正本を更新、要判断のいずれかを決める。 |

## 監査ルール

- まず「正本に何が書いてあるか」を確認する。
- 次に「現挙動がどう見えるか」をCPU戦、ローカル対戦、ネット対戦の必要範囲で確認する。
- 差分があっても、すぐ実装か正本を直さず、判定区分と信頼度を付ける。
- 高優先度は、実装修正時にテストで固定する。
- 中優先度は、スクリーンショット、録画、再生イベント、効果音の発火条件で確認する。
- 未決定のものは、正本に「未決定」または「要判断」として反映してから実装する。
- D: 未確認の項目は、実装変更の根拠にしない。
- `01-rulebook.md` が dirty、または仕様自体に疑義がある場合は、`cards/catalog.json`、`cards/card-interaction-effects.ts`、focused test、root 実装、現行挙動メモを並列に照合し、単独の文書を絶対視しない。
- `docs/plans/*` などの履歴・設計途中文書は現行仕様の根拠に使わない。現在形の説明を持つ文書が食い違う場合だけ、更新または監査記録の対象にする。
