# 正本/ AGENTS.md

## Boundaries

- 「このカードはこう振る舞うべき」と書く。プレイヤーから見える効果、状態、音、演出、失敗条件のみ。
- 実装ファイル名、関数名、内部イベント名、内部データ構造を正本の根拠にしない。
- 同じ原則を複数文書へ書き写さない。責務を持つ文書へ寄せて参照する。
- 仕様未決定の挙動は「未決定」と書く。実装に合わせて曖昧にしない。
- ランダム効果は、誰の画面でも同じ結果になるべき対象決定として書く。
- ネット対戦、CPU 戦、ローカル対戦で最終結果が変わる場合は、別仕様として明記する。
- `01-rulebook.md` がゲーム仕様・UI 表示仕様の一次情報。正本は「あるべき挙動」の裏付けで、`01-rulebook.md` を先に更新する。

## Update rule

- カード効果、演出、効果音、ネット対戦で見える挙動を変えるときは、`01-rulebook.md` を先に確認・更新し、このフォルダの該当正本も同じ意図に合わせて更新する。
- 正本と実装が食い違う場合は、`01-rulebook.md` と該当正本のどちらが古いかを確認してから直す。
- 原則として確認済みの正本を満たすように実装を直す。ただし正本自体が古い、または仕様判断が必要な場合は、先に正本を修正してから実装する。
- AI エージェントは依頼の範囲で正本を編集できます。コードを含む他の変更の可否と手順は、ルート `AGENTS.md` とユーザーの依頼に従います。

## Verification

- ドキュメント更新時は、対応する `01-rulebook.md` / `cards/catalog.json` / `正本差分監査.md` のどれを更新したかを最終報告に含める。
- 正本の追加・修正は、それを受け持つカード挙動・演出・効果音の該当テスト・該当 AGENTS.md と整合するかを必ず確認する。
- AI エージェントが正本を編集した後、`docs/AGENTS.md` のアーカイブ基準を乱していないか確認する。
